# Rust Architecture

The Search Metadata v2 candidate retains schema 8 for ordinary local writers and
admits completed schema-9 server snapshots read-only. Server migration is explicit;
building a local directory index keeps its actual schema and format. See the
[candidate migration and release plan](https://github.com/Freedragonlancer/AudioLib-Explorer/blob/codex/release-090-prepare/doc/Rust_Release_0.9.0.md).
The published-version baseline below is separate from this unreleased candidate.

The candidate uses catalog revision 2 and separates read support from write roles:
known complete snapshots 3–9 are read-only inputs, ordinary local writers target 8,
and only the explicit server writer opens completed 9 for writes. Restore/maintenance
retain their schema-8 guard; schema-9 root relinking uses the dedicated server path.
The server reports its actual write format and source schema separately from the
negotiated representation. Its default-enabled `legacy_snapshot_enabled` transition
serves a WAV-only owned schema-8 copy of a schema-9 source, without rebuilding main
FTS or changing source audio, business IDs or annotations. Native/legacy caches and
jobs are separate and source-revision bound. Turning it off refuses old peers while
retaining their valid offline cache. The candidate program version is frozen at 0.9.0;
release acceptance remains pending, and 0.9.0 has not been published.

Owned schema-9 staging validates SQLite/main FTS and directory FTS, exact folder
membership and disjoint run coverage before publication. Ordinary read-only opens
do not issue writable FTS integrity commands against an untrusted cache. The optional
local schema-8 directory index owns built-in SQL capture triggers and a persistent
dirty queue, so an older writer's folder/member changes invalidate readiness rather
than silently omitting new files. New writers consume that queue incrementally with
index updates and generation changes in one transaction; Metadata annotations do
not dirty directory membership. Preparing that index never relabels schema 8 as 9.

`AudioFile` is an owned copy-on-write presentation snapshot. Cloning a result page
shares immutable complete records; mutable field access first detaches the whole
`AudioFileData`, including strings, nested Metadata and shared-album values. Caller
edits cannot change a retained page or another response and do not imply a database
write. The private `Arc` does not escape. JSON fields, defaults and required-field
validation remain the bare-record contract; `AudioMetadata` and stored attributes
remain owned `serde_json::Value`. Rust callers construct `AudioFileData` and convert
it with `AudioFile::from`, or consume an `AudioFile` with `into_data` before moving
fields. This changes Rust construction syntax without changing the HTTP/snapshot
wire format. Cache entry, generation and encoded-byte budgets remain unchanged;
the extra allocation when hydrating a row must still be covered by performance
acceptance rather than assumed free.

First-page lookup serializes the exact normalized request into a 2 KiB stack
buffer before taking the cache mutex. Larger keys spill into bounded owned
storage under the unchanged 1 MiB encoded-entry limit. A hit borrows those bytes;
only a stable, cacheable miss acquires an owned request and key, without another
serialization. This removes common lookup-key allocations; result vectors,
normalization and cursors can still allocate. Revision proofs and encoded cache
budgets are unchanged.

AudioLib Explorer `0.8.3` uses the Rust workspace and schema 8 / Plan B storage, including shared album entities and original Metadata JSON TEXT. The writable format is `ale-s8-cld1-t3-m2-p1-a1`; Metadata compression is deferred. The snapshot's outer zstd transport remains enabled. See [shared albums and Metadata storage](https://github.com/Freedragonlancer/AudioLib-Explorer/blob/main/doc/Rust_Shared_Albums.md), the [shared migration contract](api/Library_Migration_Compatibility.md), [artwork contracts](https://github.com/Freedragonlancer/AudioLib-Explorer/blob/main/doc/Rust_Artwork.md) and [storage CR record](api/Search_Storage_B_CR.md) for compatibility, retirement and recovery. Earlier development-version measurements remain historical evidence.

This document supersedes Python-specific implementation choices in Technical_Architecture.md. Its Appendix A remains the terminology reference. The Python implementation and its test scripts have been removed from the working tree; earlier committed versions preserve their history. The original SQLite database and local config/audiolib_config.yaml remain read-only migration inputs. New features use the Rust workspace.

## Layers and contracts

The Slint desktop and CLI share owned domain contracts in `audiolib-core`. Library business operations use `DataProvider`: search, audio lookup, folder browsing, Metadata editing, scan history and statistics. `audiolib-db` supplies the local SQLite provider and `audiolib-remote` the server-mode provider. Client-local playback history uses the separate `audiolib_db::local_play_history::LocalPlayHistory` API in both modes; it is not part of `DataProvider` or a server snapshot.

`audiolib-update` handles public GitHub Release discovery and program-file deployment for the Windows desktop and supported server targets. It does not open a library or load preferences. Startup checks and verified downloads run off the UI/HTTP event loops; installation requires user confirmation and the existing shutdown barriers. Windows hands deployment to a private helper after exit; Unix servers drain writers before replacing files and executing the new program in the same process. Mac desktop updates use manual bundle replacement, with an explanatory UI instead of automatic check/install actions. See [automatic updates](Rust_Auto_Update.md) for channels, package identity, rollback and installation boundaries.

`SearchRequest` contains a query, folder scope, descendant policy, typed filters, limit, offset and allowlisted sorting. `SearchPage` returns owned results, total count and measured execution time. `MetadataPatch` edits only library annotations. `ScanProgress` distinguishes running, completed, cancelled and failed scans.

The desktop groups search and navigation state into up to 30 independent tasks for the current data source. Each task owns its query and unsubmitted filter drafts, directory scope/expansion, sorting, pagination, selection and list view position; task identity joins the existing request and library/source generations on asynchronous publications. Overflowing tabs scroll horizontally with left/right navigation and automatic active-tab reveal; the new-task control remains beside the scrollable strip. The result and facet workers remain bounded and background tasks refresh on activation. Completed task-page caches require the same provider identity and a matching `DataProvider::search_revision`, so external writes and snapshot replacement cannot validate an obsolete page. Audio output and the playback session remain global: restoring task selection updates details without issuing Load or Play. Metadata drafts retain their shared file identity, edit revision and ordered write barriers. See [search tasks and saved searches](https://github.com/Freedragonlancer/AudioLib-Explorer/blob/main/doc/Rust_Search_Tasks.md).

Personal saved searches and the restorable open-task group use owned core contracts through `DataProvider` and a separate client-local workspace store under the user data root. Scopes reuse canonical local-library identity or the server library ID; connection-profile URLs and replaceable snapshot filenames do not identify a workspace. Audio favorites remain library Metadata, while named search favorites save validated search definitions and require an explicit update after editing. This client-local feature changes neither the library schema nor the server HTTP/snapshot format. Application restart restores tasks lazily without restarting audio, and switching libraries saves and replaces the entire task group.

Tasks and favorites persist optional explicit-name provenance so automatic labels never overwrite a user rename. Restored references use source-aware stored path identity instead of the reader OS's case folding. `DataProvider::find_folder_by_path` complements audio path lookup with exact-first, ambiguity-refusing resolution; read-only snapshots do not probe the reader's source filesystem. Both SQLite lookups pin candidate selection and owned-row projection to one read transaction, preventing an externally reused ID from redirecting the returned record.

The audio results table shares column widths between its header and virtualized rows. Drag a header divider to resize, double-click it to restore that column, or use Columns to restore all widths. Horizontal scrolling keeps the header and rows aligned. An independent empty-result ScrollView preserves the full column extent when Slint's empty ListView resets its measurement. Hidden viewports cannot update the shared header offset; the populated ListView synchronizes after its full column extent is measured. Header clicks toggle ascending/descending order over the entire search result, reset pagination and retain an ID tie-breaker; Format orders by sample rate, and Tags orders by annotation tags with source tags as a fallback for empty annotations. Annotation sort keys use Rust Unicode trim and the same ICU casefold as source keys; the read-only scalar leaves stored annotations and original Metadata intact. The sort menu also retains Relevance and Modified. Logical-pixel widths and initial sort preferences for new tasks live in `settings.json` under `audio_table`, with bounded, backward-compatible defaults; existing task sort orders live in their own workspace definitions. A coalescing preferences worker saves off the event loop and shutdown flushes the latest captured layout.

`DataProvider::search_folders` applies the same query and filters to directory navigation. It aggregates matching files by folder, rolls up descendants through the closure table and returns only positive counts. It ignores the selected folder, result pagination and sorting so other matching branches remain available for cross-filter navigation. A zero-hit selected folder retains its breadcrumb scope while disappearing from the tree; All sounds or another matching folder changes the scope. Clearing search restores directories allowed by the remaining filters. A fixed result-page worker and a fixed directory-facet worker run in parallel, each holding one latest pending request with the same captured provider, generation and cancellation token. The event loop publishes a successful page before applying its facets, and marks Ready only after the corresponding directory model is published. Page failure cancels/discards its facets; generations reject obsolete publications for both. Broad directory aggregation does not delay publication of an already available result page. Expanding a branch uses the owned directory matches rather than a separate search for each folder. The facet worker retains one query/filter snapshot for page, sort and folder navigation, including a Weak provider identity that neither reuses another library cache nor holds an old library open; writes, scans, explicit searches/refresh and library switches advance its revision before enqueuing work. A superseding navigation cannot undo that invalidation. New requests cancel the previous SQLite VM operation through a per-reader progress handler, including directory aggregation; reader return removes the handler before pool reuse. Folder refresh uses shared owned snapshots and builds its lookup data off the event loop; an immutable Slint model converts only requested viewport rows instead of eagerly allocating UI strings for every visible directory. Library totals refresh at startup and library-information refresh points (F5, scan completion and library operations), rather than scanning every audio row on every tree expansion. Facet reuse also checks `DataProvider::search_revision` before and after reads; SQLite uses one dedicated read-only `data_version` observer to detect own and external commits without full-table scans. Providers without a revision disable this cache. Invalid input cancels superseded jobs before validation, and independent library-information generations reject stale statistics and errors.

Schema v3 introduced structured scan issues and library-stored playback events. In the schema-6 library-management contract, `library.rs` defines owned contracts for backup/restore, integrity, maintenance, batch annotations, file visibility, scan history and streaming transfers. `DataProvider` implements these alongside relinking and database-only removal; GUI and CLI do not access SQLite directly. Actual legacy playback events may be imported into the independent client-local store without inventing events from historical counts. The old counts and timestamps remain in the original source and pre-upgrade backups after their main-library fields are retired. [Library management](Rust_Library_Management.md) specifies user-facing operations.

The UI never blocks on scans, searches, audio probing or Waveform analysis. Background requests carry generations to reject stale responses. Selection uses one fixed Metadata/record worker and one fixed audio worker, each with a single latest pending request rather than one thread per click. Superseding selections, source gates and shutdown cancel obsolete Metadata-barrier waits and publications. Results are paged in groups of 200 and displayed through Slint's virtualized ListView. Source PCM is never represented as individual UI nodes.

Native selection uses Windows common dialogs or macOS folder/open/save dialogs through the system `osascript` helper on a worker. Prompts and file types are separate arguments to constant script text; cancellation retains the existing draft path, and returned absolute UTF-8 paths preserve filename whitespace. Finder reveal/open actions resolve canonical local targets on workers. Helpers are synchronously reaped by their owning worker. Closing during a pending selection retains the window until the worker completes and then closes without starting the selected operation.

GUI and IPC Stop invalidate pending selection generations and clear both worker slots. Selection Load/Play and Stop enter the audio FIFO under the same short admission lock; command completion waits occur outside it through an owned `CommandCompletion`, retaining each command's result independently of later status. Successful source settings changes that retain the provider resume cancelled reads and unfinished selections with their original Metadata barrier; completed auditions are not replayed. Failed transitions preserve drafts without implicitly retrying failed writes.

Built-in themes share the registry in `audiolib-core::config` and are selected from View → Theme, outside Global settings. Theme is the first View command; Language follows it for quick English/Chinese switching through the same saved language preference. Default retains the original charcoal workbench, separate transport buttons and full-height Waveform. Studio selects its own palette, gradient surfaces, navigation rail, toolbar, result rows and Metadata inspector, plus an 88 px compact audition dock that expands for Spectral Peaks and Waveform inspection. Its compact Waveform uses a separate transparent amplitude mask with a colored played range; the original Waveform image and spectral frequency colors remain audio data. Switching themes retains the library, selected record, transport, transforms and view state, and does not request playback. The two audition facades instantiate only one active presenter, within its own workbench ScrollView so keyboard focus can reveal offscreen controls. Shared mute and remaining-time state stays in AppWindow. Inactive workbench views cannot report scrolling or layout changes. Pending theme restores follow the current row size and yield to explicit navigation or a source reset. Presentation-only Waveform refreshes retain the selected/rendering source instead of reusing an older engine source. Themed controls retain Slint standard controls as their pointer, keyboard and accessibility owners, with non-interactive paint overlays for application accents.

The desktop groups commands under File, Edit, Library, View, Playback, Settings and Help. Scanning and scan history belong to Library; diagnostics, logs and software updates belong to Help. All workbenches use the same Slint MenuBar contract: Windows and macOS use platform menus, while the testing backend renders the standard software menu. The application name stays in the window title; search and library navigation remain in the application toolbar. An opened menu switches to another top-level entry on pointer hover; hovering a closed menu never opens it, and dismissal ends that interaction session. Settings → Global settings (`Ctrl+,`) opens one dialog with General and interface, Search and tasks, Playback and audio, Server and synchronization, and Local caches pages. Language, typography and ordinary preferences apply immediately. Audio output and shared synchronization use independent drafts and explicit apply/save actions; changing pages preserves those drafts, and closing prompts before discarding unapplied changes. Shared synchronization updates only polling and automatic synchronization, independently of connection drafts or provider selection. Library-specific Waveform generation and server connection credentials remain in library management. Local cache clearing retains its own scope and confirmation, and does not remove libraries or source audio.

The search toolbar bounds the keyword input instead of stretching it across the window. Spare horizontal space remains available for future search controls. The current-source status grows independently and exposes its complete displayed summary in a hover tooltip in every workbench.

The 0.2.0 desktop uses a compact search workspace, collapsible advanced filters and a hideable Metadata inspector. File and folder ContextMenuArea menus capture owned IDs/paths when opened; actions do not use row positions that a search refresh can change. Opening a menu preserves the audition. File quick edits update only favorite for other records and merge pending inspector edits for the current record. Save completion preserves edits typed while its write was running. Search refreshes retain the visible selection by ID. Keyboard transport is scoped to the result list so spaces in text editors remain text input.

The results toolbar combines visibility, filters, sorting and the inspector toggle in one 32px row. Multiple selection replaces the title with a selected-count menu (batch edit, clear and database-only removal); wide layouts also expose batch edit and removal beside it. No extra selection row reduces the result viewport. Breadcrumbs appear only inside a folder; Select page shares the pagination footer. Each virtualized result row is 32px high and shows the filename without a repeated directory path.

The library sidebar and Metadata inspector have draggable 12px dividers, also adjustable with Left/Right arrow keys when focused. Their initial widths are 198px and 320px, with bounds of 170–480px and 240–600px. Resizing reserves at least 520px for results, and temporarily clamps panels when the window narrows without discarding their preferred widths. Hiding/reopening the inspector preserves its width for the current window. Batch buttons depend on the results area's width rather than total window width; all five result columns remain available through horizontal scrolling. The supported minimum window remains 1080×700 logical pixels.

The sidebar's Folders and Libraries headers independently expand or collapse their lists. When both lists are open, their horizontal divider adjusts the height split by dragging or focused Up/Down keys; an expanded list uses the remaining space when the other is collapsed. The split preserves at least two rows in each expanded list and survives temporary window constraints. Expansion states and the preferred height ratio persist under `window_layout` in `settings.json` through the existing preferences worker. These layout actions preserve the active folder and library filters.

The Metadata inspector hides its form without a selection and keeps save status/actions outside the scrolling fields. Extracted description and read-only tags from canonical keywords/category fields appear before annotation controls, file path and the original Metadata disclosure. Original Metadata (including SMED) is collapsed by default and collapses again when the displayed file ID changes. Derived source tags never replace editable library tags or alter source Metadata. Favorite is a single star button in the inspector header. Notes are collapsed by default and collapse again when the displayed file ID changes; a dot indicates existing notes. The color editor is hidden and inspector writes omit color, preserving both legacy values and changes made by other writers after the file was displayed. All dimensions are logical pixels; edit revisions and save ordering remain unchanged.

The source description and tags reset their inner scroll positions and selection when the displayed file ID changes, including when two files share the same text. Keyboard navigation and selection inside long source tags scroll the cursor into view; these read-only interactions do not create annotation drafts.

Metadata writes use one FIFO worker and per-file draft revisions. The displayed file identity and inspector values change together on the UI event loop. Selection reads wait for preceding writes and overlay any pending draft, including when returning to a previous file. A save result acknowledges only its own revision. Window close captures edits and asynchronously drains the write queue before quitting; failure preserves drafts and restores editing for a retry. Selecting All sounds also advances the directory request generation, rejecting an older tree or breadcrumb response.

Database administration drains the Metadata queue and cancels/joins scanning before executing. Provider references and UI requests carry a library generation. A successful switch clears drafts, selections, old result models and pending request identities; old completions cannot publish into the replacement library. Metadata sequence/completion counters remain monotonic across the reset so an older reader can finish waiting and exit instead of retaining a thread indefinitely. Playback sessions append only to a client-local history.db, shared by local/server modes without network reporting. A pause/resume, seek or repeat remains one session; Stop/Ended then Play starts another. Main-library DTOs/provider traits no longer expose playback fields or history methods. Compatibility server routes retain ID validation and return no history without database/revision writes. The next schema upgrade retires the history table, count and last-playback timestamp only after a verified backup and local-client legacy-history import. Scan history remains available and validates bounded pagination.

Changing a server connection captures drafts and holds a source gate against new GUI writes while draining the old connection's Metadata FIFO before publishing the new URL or credentials. The gate remains held through provider opening. Replacing a snapshot with a newer revision of the same server library also drains requested Metadata writes. Save/open failures keep the old provider, selected editor and drafts; a failed connection change restores the old settings, secrets and active cache, so a restart cannot pair one server's snapshot with another server's connection. Offline startup accepts only an active cache whose effective server URL matches the configured source.

Ordinary text input uses a **30ms production debounce**; immediate navigation and refresh keep their explicit scheduling. Superseding typing, backspacing to one letter and invalid input cancel both workers before validation and prevent obsolete page/facet publication. A standalone one-letter query does not dispatch a search. Debounce and queueing are part of GUI input-to-completion measurements.

The native “Check current page” menu item's enabled state depends only on the existing `menu-ready` operation/modal guard. Activation additionally checks the publication-synchronized `menu-has-page-rows` value, so an empty page safely does nothing. Result identity and empty/nonempty transitions do not change this item's enabled binding. This avoids triggering Slint's complete native menu reconstruction just for that flag; other genuine menu-state changes can still rebuild the menu. Actual empty models are still published.

The explicit Windows GUI diagnostic captures only its own HWND; normal application mode installs neither WGC capture nor the synchronous geometry guard. Completion requires an observed CRC-valid WGC compositor frame with matching nonce/request generation and phase ALL after actual page and complete directory-model publication. Own-process identity, foreground, visibility, input desktop, complete client/frame monitor-workarea coverage and conservative application/unknown-occluder checks remain mandatory. Only an explicitly configured, identity-pinned Sky pointer-decoration exception is recognized. Native history rejects every outer-window/frame or DPI change, including a later restoration. A client-only layout transition must restore the complete armed client geometry; the accepted frame timestamp must be at or after its restoration. Capture rejection, native-query failure, unresolved layout, history/message overflow or failed guard removal invalidates the sample. The menu repair does not weaken these gates. WGC observation is not panel scanout or proof of continuous absence of all possible occlusion; synthetic Slint dispatch and native input-hook populations are reported separately.

## SQLite migration and search

WAV Metadata now includes LIST/INFO, arbitrary iXML USER/vendor fields, aXML, XMP, ID3 text and legacy Soundminer SMED fields. These source fields participate in FTS5 without replacing user tags; index rebuilds use the same derived text. Incremental scanning checks the extraction version as well as the file fingerprint, refreshing older records once. The inspector shows the preferred source description while retaining the original BWF value and all parsed fields. See [WAV Metadata](Rust_Wav_Metadata.md) for formats, bounds and private-format compatibility.

MP3, AIFF/AIFC and the `.bwf` alias use that owned Metadata/search pipeline. PCM byte order, sample kind and storage width are explicit, so AIFF is not decoded as little-endian WAV. MP3's validated scan layout supplies exact remote playback length without fetching every network frame header. New sources atomically require the exact `audio_sources:1` (`af1`) format variant while retaining schema 8/9; base libraries remain base. Old snapshot peers either receive the existing WAV-only legacy representation or are refused an unknown exact format. Already-open older local instances, including readers and writers, must be closed before a shared library first enables new sources. See [source formats and limits](Rust_Wav_Metadata.md).

First launch imports the configured legacy database using the SQLite backup API. Migrations execute on the new copy, with versioned schema and integrity checks. IDs, source Metadata, user tags, ratings, notes, colors, scan history, playlists and project references survive. The schema-6 recipe explicitly retires `play_history`, `audio_files.play_count` and `audio_files.last_played_at`; old values remain in the original source and rollback backups. Client-local history is imported idempotently after backup and before library mutation; server/snapshot jobs never import it. Independent history storage is scoped under the client data root and survives snapshot/cache replacement. Derived FTS5 and hierarchy indexes may be rebuilt. The original source database is preserved for repeatable import and recovery; import never modifies it.

FTS5 indexes searchable Unicode text plus derived filenames, tags, notes and source descriptions. Terms containing non-Han letters support contiguous fragments of at least two searchable Unicode graphemes (combining accents do not count separately): `ex`, `expl`, `plos` and `sion` all match `explosion`. ICU4X case folding and canonical decomposition remove combining accents before encoding adjacent scalar pairs as fixed-width ASCII tokens in derived logical FTS fields. Schema v6 computes these values during indexing instead of persisting token columns in audio_files; supported legacy v3–v5 sources retain their older stored columns. An FTS5 phrase over these positional bigrams enforces continuity within one field, with a separator between words; storage and generation work are linear in input length. Query compilation ORs that phrase with a complete-word match restricted to original columns, preventing user text resembling an encoded token from matching unrelated derived data. Multiple terms remain AND conditions across searchable fields. A lone non-Han letter waits for more input in the GUI and fails core validation before a database search; this also cancels older page/facet jobs. Single letters within a multi-term query retain exact-word semantics for codes such as `P-51`. Empty browsing, Han characters and numeric-only terms retain their prior rules. Han runs keep jieba's normal query segmentation and search-mode indexing with the shared audio dictionary; original-column matches use `unicode61 remove_diacritics 2`. English Porter stemming is removed: longer queries such as `explosions` do not match shorter words such as `explosion`. Dot/underscore compounds retain their complete-word phrase alternative and exact numeric/single-letter components in source-only Metadata; positional guards prevent numeric phrases from crossing intervening letter components. Punctuation and words such as OR remain text rather than user-supplied FTS operators. Legacy external-content triggers remove old-value FTS5 entries before inserting updated values. The v6 contentless-delete triggers use ordinary DELETE by rowid; inserts and searchable-field updates project all twelve logical values into the new index entry. User values are parameterized; SQL order expressions come from the Rust SortOrder enum. Search filters and counts share the same predicates. Queries are bounded to 500 characters.

The historical schema-6 contract used `user_version=6` and specific schema-3/4/5/6 format IDs; current read/write roles are defined above. Required feature revisions remain authoritative: an integer range alone never grants compatibility. Schema 6 uses contentless-delete FTS5 with all twelve logical fields, full positions and document lengths. Six persisted token columns and the authorized playback objects are removed; `search_storage=1` and `play_history_retired=2` identify p1. Earlier unpublished p0/retired=1 remains read-compatible and has an owned path to p1. Schema v4 adds performance indexes; v5 removes rating indexes while preserving the rating column and its data. Source tags use an additive derived column and index. Additive implementation revisions live in `audiolib_schema_features`: `stable_audio_ids`, `foreign_key_indexes` and `search_indexes` use revision 1; `tokenization` uses revision 3. Revision 2 introduced positional letter fragments; revision 3 also indexes a single source grapheme when full case folding expands it into multiple searchable letters, so `ss` finds an independent `ß` term and `ff`, `fi` and `ffi` find `ﬃ`. The exact single-grapheme token remains available inside multi-term queries, with positional separators around both encodings. Query input still needs at least two searchable graphemes for a standalone letter search. Existing revision-2 text requires the shared owned migration path, including the supported legacy normalization steps; read-only snapshots are upgraded only in an owned copy. The `search_indexes` revision adds two narrow covering indexes without rebuilding FTS5 or changing Metadata:

```sql
CREATE INDEX IF NOT EXISTS idx_audio_search_facets
 ON audio_files(id,missing,folder_id);
CREATE INDEX IF NOT EXISTS idx_audio_visible_tagged_folders
 ON audio_files(folder_id,id,user_tags,source_tags_text)
 WHERE missing=0 AND (COALESCE(trim(user_tags),'')<>'' OR source_tags_text<>'');
```

Writable startup uses the shared inspect/plan/apply/resume/verify/rollback engine. Supported migrations acquire the administration, scan and upgrade leases, retain an immutable original backup, guard the source and build an owned candidate in committed 5,000-row copy/index batches. Candidate checkpoints are validated before resumption; full business/FTS validation precedes atomic SQLite publication and checked WAL truncation. Legacy rev-3 recovery runs only inside the owned normalization copy. Local GUI, CLI and server use the same executor and report committed progress. Unknown future formats/protocols block writes instead of being downgraded or declared unrecoverable from a version number. Fresh creation is atomic; remote cache conversion may restart from the intact cached source. Unknown extension data, annotations and all non-retired fields are preserved. No WAV rescan is required. See the [shared migration contract](api/Library_Migration_Compatibility.md); [legacy upgrade recovery](Rust_Upgrade_Recovery.md) documents the older protocol.

Present visibility means exactly `missing=0`; the required `idx_audio_files_not_present` partial index covers `missing IS NOT 0`, including nullable legacy rows and unknown nonzero values. Sparse exclusion probes use this index explicitly, while Missing visibility keeps its existing `missing=1` contract. Owned DTOs conservatively expose NULL and unknown values as missing without rewriting their stored values. New scan inserts explicitly set zero even when a legacy column has no default. Read-only libraries missing a required search index or revision are upgraded in an owned copy.

Audio identities use the persistent single-row `audiolib_audio_id_sequence` high water, updated by explicit insertions and allocated transactionally for newly scanned files. Removing a record never lowers it; restore retains the destination's already-issued high water alongside the restored source. Fresh empty libraries begin at ID 1. An older library without this sequence initializes above its retained IDs/legacy SQLite sequence and a conservative Unix-epoch-milliseconds ×1024 baseline. This separates new IDs from ordinary old small IDs; the old format cannot reveal arbitrary deleted i64 identities, so the baseline is not proof of their recovery. Foreign-key and database-only removal lookups index `audio_file_id` in `playlist_items`, `project_references` and `waveform_cache`; old `play_history` indexes are retained only in the pre-upgrade backup.

Read-only opens do not migrate the source file. A supported schema-v3/v4/v5/v6 source with older search text or a missing required directory-rollup, non-present or covering search index is backed up from a pinned read snapshot into an owned temporary directory, validated, upgraded without WAL dependencies and validated again. The provider retains that directory until all of its SQLite connections close; `database_path` identifies the actual temporary snapshot. Reopen to observe later commits to the old source. Current search revisions retain the original path and normal reader behavior. Downloaded remote snapshots are likewise validated before owned staging upgrades and validated afterward; bad triggers cannot be concealed by a rebuild. Offline cache upgrades publish a new owned filename and cache state while retaining the original snapshot for existing readers. Upgrade failure keeps the prior cache usable or permits the startup placeholder.

Readers reuse an idle pool bounded to four retained connections, with a 64MiB SQLite page-cache budget per connection. Writers explicitly use `mmap_size=0`. Reader setup calls `sqlite_reader_mmap_bytes(path)` before query snapshots: only canonical paths on verified Windows fixed volumes request the `SQLITE_READER_MMAP_BYTES` ceiling of 68,719,476,736 bytes (64GiB). Network, removable, unknown and all currently unverified non-Windows volumes (including macOS) request zero. Setting `AUDIOLIB_DISABLE_MMAP` to any value before startup disables every reader mapping; this also covers USB disks Windows reports as fixed. Auxiliary readers and benchmark probes use the same policy. The bundled build sets `SQLITE_MAX_MMAP_SIZE=68719476736LL` to permit this ceiling beyond the former platform default. The VFS may impose a lower effective limit or use ordinary reads when mapping is unavailable. File mappings are demand-paged and mappings of the same file can share OS-backed pages; the ceiling is not a resident-memory reservation per connection. The separate per-connection SQLite cache budget remains 64MiB. See SQLite's [memory-mapped I/O contract](https://www.sqlite.org/mmap.html). Full-library integrity checking holds the same restore/read gate but opens a separate read-only connection with mmap disabled on both backup connections; traversing every database page must not populate a pooled search mapping for the entire library. This controls that mapping residency, without claiming a hard RSS cap for integrity work or the process. Each ReadLease owns its non-Sync connection exclusively; the revision observer stays under its mutex. Both use rusqlite's default NO_MUTEX mode to avoid redundant SQLite connection locking. Search caches ranked IDs and document lengths, never owned result pages or Metadata. For nonempty relevance queries, each request explicitly maps the hidden FTS5 rank column to `audiolib_bm25()` when snapshot lengths are available or the bounded sparse plan below explicitly selects native per-match sizes; unsuitable-length fallback uses native `bm25()`. For valid FTS5 data, the private rank function follows native default BM25 arithmetic, ordered by score and then ID. Native-oracle tests permit at most two ULP for finite values with matching signs because C/Rust compiler contraction and platform math can round differently on aarch64; row order remains asserted exactly. Snapshot/layout identity remains bit-strict, and no runtime score-comparison fallback is involved. Folder scope, visibility and other filters are applied within the pinned reader snapshot before current Metadata is hydrated. Alternative sorting retains the allowlisted SQL selection path.

The benchmark probes mmap configuration only after every timed call has completed, using a new read-only connection to the same file and the same requested ceiling. `mmap_requested_bytes` records the request; `mmap_bytes` records the configured upper limit read back from that probe, with `mmap_reporting` describing its scope. These values measure neither actual mapped length nor resident RAM, and do not establish that every timed connection mapped every eligible page. The probe cannot warm pages before the measured first-provider calls.

For existing production snapshots, `search-benchmark --existing-db <snapshot> --request-file <requests.json> --first-only --case-index <index>` measures the selected request before opening a shared provider, collecting library statistics or running initial/warm searches. The JSON file is a validated nonempty array of owned `SearchRequest` values, capped at 1MiB. `--case-index` selects its original ordinal; custom requests cannot combine with built-in query/edge/fragment selection. This mode requires current derived search state and refuses implicit snapshot upgrading, then verifies that the provider's canonical database path equals the requested source. Each selected case opens a fresh read-only provider and measures search followed by directory facets; independent first-process repetitions launch the executable separately with one case. It reports provider opening separately, exact result IDs and sorted folder ID/count pairs after the timer stops, and collects row counts, visibility totals and SQLite configuration only after every timed call through the narrow facet covering index. It does not produce shared-provider warm percentiles. The original mixed synthetic/first-provider mode retains its earlier statistics preparation and workload, so it must not be described as having this stricter no-pre-query-statistics protocol. Neither mode flushes the OS page cache or measures GUI input-to-paint time.

The private rank function normally decodes the 12-column `audio_search_docsize` lengths once per pinned snapshot. Its owned length cache is bound to the dedicated observer's `data_version` revision and contains at most 16MiB across one or two dense ID domains. Construction may temporarily retain up to 32MiB of staging pairs alongside the final 16MiB payload. The same ordered staging IDs provide seven actual rowid quantile boundaries for eight scoring ranges on sufficiently large snapshots; splitting does not assume positive, contiguous identities or issue additional offset scans. These are component payload bounds, excluding old in-flight references, other caches and process allocations; they are not a total process-memory cap. Sparse or excessive ID layouts and allocation limits select native BM25. Missing or malformed length slots use native `xColumnSize(-1)`, preserving the native document-length error rather than treating damaged data as zero; SQL/I/O errors and cancellation propagate. A connection-borrowing registration guard keeps the private FTS5 callback's snapshot reference alive until its statements are finalized, then clears that reference before the reader returns to its pool; overlapping registrations are rejected.

A cold complex query with verified helper preparation may defer the full docsize scan until exact global phrase statistics are complete. Eligibility requires a multi-token positional phrase and a nonclamped integer phrase-DF sum no greater than `min(N/8, 65,536)`. This sum conservatively bounds query matches; overlapping alternatives can overcount, while an early-stopped phrase or integer overflow makes the bound unavailable. The selected sparse plan drains helpers and scores serially with the same prepared global IDF/private arithmetic, obtaining native `xColumnSize(-1)` only per match without publishing a full length cache. Warm same-revision lengths and single-token/two-letter queries keep their overlap paths. A common or excessive cold complex result returns to full length loading after DF preparation, which can lose overlap and requires measurement. Cached-length and native-per-match private scores retain identical bits; the independent C oracle retains its existing two-ULP bound. `sparse_native_length_selections` reports this plan choice separately from worker-failure fallback counters.

Each request-owned `Prepared` plan initially binds one complete compiled MATCH expression with no document lengths or published statistics. The root uses a private preparation auxiliary function on the first matching row to read only a lightweight `Layout`: phrase/column counts, global document count, average length and individual phrase token sizes. This step neither loads docsize nor enumerates phrase document frequencies, and its cursor is finalized before helper startup. No matching row returns an empty ranking without further preparation.

Preparation and scoring use separate gates. A stable snapshot with at least 262,144 FTS5 documents may start up to seven temporary helper readers, capped at logical CPU availability minus one (zero means serial); one reservation permits at most one fan-out per provider. Each helper opens a read-only connection and pins its transaction before reporting ready. The root opens the first, preparation gate only after all active helpers are ready and the dedicated observer still matches its original snapshot revision. Helpers enumerate global document frequencies for disjoint phrase groups, initially balanced greedily into seven groups by phrase token size and coalesced round-robin across the active helpers: each whole phrase belongs to exactly one group, and groups may be empty. The root normally reads or reuses its snapshot's owned docsize lengths concurrently; a cold complex sparse probe first waits for the complete DFs as described below. Every helper still binds the identical complete MATCH expression; phrase groups divide preparation work, without restricting the documents used for IDF. The root retains its read gate while helpers drain, and helpers avoid reacquiring that gate so a waiting administrator cannot deadlock startup.

Each helper returns typed owned `PartialStats` retaining original phrase indices. `complete_preparation` rejects missing, duplicate, invalid or mismatched entries before publishing anything: all phrases must appear exactly once, with the same document/column/phrase counts, phrase sizes and average-length bits as the root's `Layout`. Only the complete result is published once as immutable global `Stats` in original phrase order. The root separately supplies its optional document lengths before scoring. Length references are cloned during cursor initialization; scoring rows do not acquire the prepared-length mutex.

Each worker enqueues at most one readiness message and one `PartialStats` message, including workers assigned an empty group. Errors or panics set the shared abort flag without sending another readiness or preparation message. This keeps either bounded queue from filling with duplicate messages while cancellation cleanup joins another publisher. Receivers observe abort during their 20ms bounded waits or channel disconnection, and cleanup releases both gates before joining workers.

The second, scoring gate opens only after complete statistics and suitable lengths have been published, seven valid rowid quantile boundaries exist, and a large snapshot has a phrase reaching the IDF clamp threshold. The root and up to `min(available_parallelism()-1, 7)` helpers then score disjoint rowid ranges (the prepared eight quantile ranges are coalesced for fewer CPUs) using the same complete MATCH expression and shared global statistics; each scoring cursor owns its mutable phrase-frequency buffer. If parallel scoring is unsuitable, the helpers drain and the root scores serially, reusing complete prepared statistics when lengths are available. Missing or unsuitable lengths retain the real native `bm25()` fallback, except for the explicit bounded sparse selection below. Unavailable preparation resources or a snapshot-revision race drain the helpers and discard incomplete partial statistics; serial initialization remains in the root's original pinned transaction rather than interpreting partial results as a complete plan.

Phrase document-frequency enumeration stops once its match count reaches `ceil(N/2)`, where `N` is the FTS5 document count: native IDF is then nonpositive and clamps to exactly `1e-6`, so remaining matches cannot change the score. Scoring uses `xPhraseFirst`/`xPhraseNext` to count each phrase's occurrences directly instead of merging all phrases into the `xInstCount`/`xInst` array. Default column weights remain one, with one floating-point increment per occurrence and native phrase/arithmetic order. Healthy-index scores agree with native default BM25 within the bounded floating-point oracle described above. Early frequency termination and direct position-list iteration do not promise the same error timing as native BM25 on damaged or unvisited position lists.

The root and helpers share the 2,097,152-row complete-ranking budget, reserving in batches of 1024. Unused reservations can conservatively exhaust the budget before that many rows are retained; exhaustion requests the existing exact SQL pagination fallback without publishing a partial ranking. If auxiliary scoring becomes unavailable, workers drain and the root resumes its unconsumed scoring cursor in the original snapshot, discarding partial helper rankings. Genuine SQL/data failures propagate; cancellation stops and joins every helper before releasing its reservation and reader resources. Each range is read with `ORDER BY rowid ASC` and concatenated in range order. A stable sort by the exact score therefore preserves ascending ID as the tie-breaker. Temporary readers each use an 8MiB SQLite cache budget and the same volume-gated mmap policy as ordinary readers, adding at most seven active connections beyond the idle pool: at most 7×8MiB (56MiB) of auxiliary SQLite cache budgets. One master plus seven helpers therefore budget 120MiB of SQLite page caches; four retained ordinary readers can still retain up to 256MiB independently. The revision observer and writer have separate budgets. These component limits are not peak RSS measurements. OS-backed file pages can be shared across those mappings; this does not multiply the configured ceiling into a fixed physical-RAM allocation. Their tuple vectors, thread stacks and the stable-sort buffer are additional temporary allocations, outside the retained ranking cache's unique 32MiB payload budget and any total-process-memory claim.

Unavailable-reader, lock, worker-start and snapshot-race fallbacks emit one debug event with a fixed reason and increment process-wide `parallel_ranking_diagnostics()` counters, without recording queries or paths. `search-benchmark --concurrent-writer` is restricted to generated owned fixtures and compares fresh-provider searches with and without committed annotation writes; it reports counter deltas alongside latency. The 50ms worker busy timeout remains bounded so cancellation and joining do not wait on the ordinary 5-second reader timeout.

The repository's `.cargo/config.toml` supplies `LIBSQLITE3_FLAGS=-DSQLITE_DEFAULT_MEMSTATUS=0 -DSQLITE_MAX_MMAP_SIZE=68719476736LL` for the bundled SQLite build on every target, including macOS aarch64. These are portable SQLite options; the mmap macro only raises a ceiling and does not enable mapping. Disabling default memory status avoids the global memory-statistics mutex on each allocator call; the mmap macro permits the separately configured 64GiB virtual mapping ceiling. `SQLITE_THREADSAFE=1`, database locks, WAL and transaction behavior remain enabled. Global allocation statistics, soft/hard heap limits and `SQLITE_MAX_MEMORY` enforcement are unavailable with memory accounting disabled; this application does not rely on those interfaces. Per-connection cache controls, SQLite's single-allocation checks and Rust's explicit bounded collections remain effective. This does not establish a total SQLite or process heap cap. See the official [SQLite compile options](https://www.sqlite.org/compile.html#default_memstatus), [memory-status configuration](https://www.sqlite.org/c3ref/c_config_covering_index_scan.html#sqliteconfigmemstatus) and [memory allocation documentation](https://www.sqlite.org/malloc.html#memory_status).

Ranking reuse is bound to the caller's pinned snapshot. Supported tracked libraries use the complete opaque lineage cookie and audio-change watermark; other libraries retain the dedicated `data_version` observer proof. A sequence is not a SQLite commit counter. Providers retain at most two generations, 16 query entries and 4,194,304 i64 slots across unique retained `Vec` payloads (32MiB), with at most 2,097,152 matches in one ranking. An order-sensitive fingerprint only filters sharing candidates: complete `Vec` equality remains authoritative before equal rankings share a canonical `Arc`. Equal membership with different ordering never aliases. Unique payload accounting charges shared rankings once and releases their budget only when their last cache entry is removed. Old readers cannot retire or repopulate a newer generation. Oversized rankings or filter membership fall back to the cancellable SQL path. Retained-cache bounds exclude bookkeeping, concurrent temporary rankings, membership sets, reader caches and in-flight references.

An optional, bounded SQL journal captures supported `audio_files` inserts, updates and deletes using built-in functions, including normal older writers. It validates its owned definitions, source recipe, schema cookie and retained prefix before reuse. Missing, changed, truncated or foreign state falls back to the full read path. Managed FTS-only rebuilds and restore discard this derived lineage and reset the provider caches. Arbitrary FTS writes that bypass `audio_files` and the administration lease are outside the supported data-write contract; the journal does not claim to capture them. Observable same-epoch unknown commits quarantine reuse through the observer fallback. No triggers are attached to FTS5 shadow tables.

Document lengths use immutable 16KiB COW chunks; a complete journal delta reads only changed docsize rows. Unsupported domains or gaps reload the bounded full snapshot. Up to two retained length payloads remain separately bounded at 16MiB each. Bulk vendor and scan writers can prepare bounded hot query rankings inside their real transaction using its current complete MATCH set, exact DF, N and average document length. Changed IDs alone are never used as a substitute for full BM25 rescoring. Candidates publish only after successful commit and a matching committed epoch check; rollback discards them. Auxiliary readers never score uncommitted writer data. Cache work holds no cache mutex across SQL and preserves the established cancellation and durable-batch boundaries. Runtime timing gates remain separate acceptance evidence.

An optional first-page response cache also retains owned Metadata from an exactly pinned database image. Its key uses the dedicated observer's complete `data_version`, rather than the audio-row epoch: folder hierarchy, album entities and other non-audio changes must invalidate pages too. Lookup brackets the actual reader pin, and cold admission brackets the complete query. Valid normalized requests have no cursor, offset zero and at most 200 results. At most eight entries across two observer generations share an 8MiB encoded key/payload budget, with a 1MiB per-entry ceiling; these are encoded-byte limits, not heap/RSS caps. Borrowed sizing precedes DTO cloning. Serialization, deep cloning, continuation encoding and retired payload destruction occur outside the cache mutex.

Vendor/scan batches capture hot request names inside their admitted writer transaction, then evaluate complete canonical SQL and current Metadata without touching shared ranking or directory caches. Successful commit grants publication while the same writer guard is retained. Publication reads the dedicated observer and then the committing connection's `data_version`; that connection must still match its admitted value, since its own commits do not advance the value but external commits do. A candidate therefore cannot absorb an unrelated folder/album commit into its identity. A subsequent commit receives a different observer key; a delayed old insertion cannot retire a newer generation. Candidates contain no sendable cursor: All/Path continuation is encoded for the reader's current committed revision. Optional preparation uses a 1.5-second budget checked between requests, not a hard SQL deadline. Unsupported/oversized pages and intact-transaction cache errors retain ordinary query fallback. Cancellation preserves durable batch boundaries; a lost business transaction remains a real error. Administrative reset clears response pages without replacing the observer. Full timing, memory and native acceptance remain distinct from these source contracts.

Writable providers may reuse up to eight unlocked handles for their persistent search-upgrade sidecar. Each query still acquires its own shared OS lock and releases it before returning the handle; idle pools do not exclude an administrator. The provider binds its original database path to the canonical sidecar once, never clones handles, and never removes the sidecar. This relies on the existing persistent-lock-inode contract. A cache-only reader keeps the same lease and read gate but can defer repeated readiness SQL: an exactly matching complete observer image was checked when its page was built. Cache misses use the ordinary checked reader, and writer candidates check readiness in their actual transaction. Accepted Main/Filename relevance pages may take priority over redundant optional ranking collection for the same compiled query; complete cold ranking, COW lengths and facets retain their normal fallback. A page's bounded IDs never substitute for a complete ranking.

Unfiltered present-file FTS counts probe at most 129 entries of the partial non-present index: zero non-present files use direct FTS counts, 1–128 subtract only matching non-present IDs through rowid/MATCH lookups, and denser missing sets retain the joined count. All-file visibility counts FTS directly. Counts and pages remain in the same pinned transaction. Present scoped/filter membership preserves `missing=0` so visible folder, format and sample-rate/duration indexes remain covering; removing this predicate would force filter fields back onto wide Metadata rows. Non-visibility-only filter intersections use one compact dense bitmap, or two disjoint dense domains for legacy small IDs followed by epoch IDs. Every ranked ID must be covered; each domain spans at most eight times its ranked count, and the combined rounded allocation stays within 1MiB (131072 u64 words). Rankings under 128 entries retain the HashSet fallback when one domain cannot fit; sparse, uncovered or excessive domains also fall back. Discovery observes cancellation every 1024 IDs without sorting the BM25 ranking. Visibility-only result-page reads avoid bitmap setup, and SQL membership row budgets remain independent of representation. Tags use literal Unicode case-insensitive substring matching through ICU4X full case folding and a deterministic SQLite function; original tag text is preserved. Colors use a validated exact hexadecimal value. Performance acceptance remains **P95 latency <500ms for 1M+ records**; benchmark conditions and results are reported separately.

For nonempty directory facets, the provider first checks for the complete query ranking in the same pinned snapshot, independently of the page's folder scope and filters. The observer-before, transaction-pin and observer-after checks must identify a stable matching revision before reuse. Visibility-only requests can reuse those IDs directly. Empty visibility-only requests retain their direct covering aggregation path, and eligible empty Present tag-only requests retain `idx_audio_visible_tagged_folders` aggregation.

When no ranking is available, cold nonempty facets can collect complete unscored MATCH IDs in their own pinned transaction, bounded to **2,097,152 IDs**. These temporary query-only IDs never enter the ranking cache or define page order. Complete empty membership skips filter scans. Every **16,384 IDs**, a nonblocking `try_lock` plus nonmutating cache `peek` may reuse an already complete ranking for the exact compiled query and proven pinned revision. It never waits for the page worker, resets a newer cache, changes LRU order or publishes partial IDs. Contention continues local collection. Oversized membership discards all partial work and retains the complete original MATCH fallback; SQL errors, poisoned locks and cancellation remain errors. Filter projection, membership, directory counts and closure rollup all remain in the same transaction. A failed filtered intersection never substitutes raw query membership for filtered counts.

Other filtered facets first project only `af.id` with all requested filter predicates and bound values, omitting query text, selected-folder scope and pagination. This staged path is eligible for complete same-snapshot ranking or locally collected query membership, including small or empty ID arrays, or an empty filtered query outside the direct tag path. The former 65,536-ID minimum is removed so a small retained ranking does not force another MATCH. Existing partial/format indexes can cover suitable filter projections before folder lookup; mixed filters are not all covered and may still require table access. `search_candidates` intersects projected IDs with the same-revision complete query ranking using a dense membership bitmap of at most 1MiB or a HashSet bounded by the ranking's at most 2,097,152 keys. Empty queries need no ranking intersection. The temporary matched-ID `Vec` retains at most 2,097,152 i64 IDs (16MiB payload); its sorting never changes cached BM25 order. Every visited filter candidate, including a nonmatch, consumes the candidate budget `min(2,097,152, 8×ranked_ids + 8192)`, or 2,097,152 for an empty query. Cold Present requests whose extra filters consist only of sample rate and/or duration instead have an independent 2,097,152-candidate budget, avoiding the small-ranking budget cliff. The optional `idx_audio_visible_filter(sample_rate,duration,id) WHERE missing=0` is forced only when its exact definition is verified; otherwise the ordinary planner remains available. Warm rankings and other filter shapes retain the original heuristic. Exceeding either candidate or matched-ID budget discards the whole staged result and selects the complete SQL fallback, never a truncated count.

A complete facet ID set of at least 262,144 IDs, from either the retained ranking or the filtered intersection, may use `search_facets` to scan `idx_audio_search_facets` sequentially. Eligibility requires the library to contain no more than twice that ID-set size and all IDs to fit one dense domain (`Dense`) or two dense domains (`TwoDense`) within a combined rounded bitmap payload of 1MiB; this scan path does not allocate a fallback HashSet. The library-size gate uses `SELECT COUNT(*) FROM (SELECT 1 FROM audio_files INDEXED BY idx_audio_search_facets LIMIT ?)` with a limit of `2×ids.len()+1` in the same pinned transaction. This bounded subquery distinguishes the threshold exactly and keeps the probe on the facet index, avoiding SQLite's native whole-table COUNT shortcut selecting `idx_duration`.

The scan bitmap is populated from every complete facet ID, and each scanned candidate undergoes exact ID membership testing before its folder count is accumulated. Equal library and ID-set counts never justify skipping membership checks. Present retains `missing=0`, Missing retains `missing=1`, and All includes every missing value, preserving legacy NULL/nonbinary flags and existing NULL-folder behavior. Domain discovery, bitmap population and filter projection observe cancellation every 1024 IDs; the covering scan checks every 1024 candidate rows, including nonmatches, while retaining the SQLite progress handler. Temporary ID vectors, membership and counters are request-local; they add no persistent cache, schema change or migration, and their separate bounds are not a total process-memory cap.

Smaller, more selective or unsuitable complete ID domains use at most 8192 IDs per JSON argument through `json_each` and a narrow covering `CROSS JOIN` on `idx_audio_search_facets`, using the same visibility predicates. Each JSON argument stays below 172KiB even for signed i64 IDs; chunk boundaries and every 1024 returned rows observe cancellation. Missing/unstable rankings, ineligible staged intersections and budget overflow use `folder_search_from` with the shared `fts_search_from` builder: `audio_search CROSS JOIN audio_files ... ON af.id=audio_search.rowid` fixes MATCH as the outer loop. Query COUNT and SQL result pages use the same outer-loop builder, including non-relevance sorting and ranking-budget fallback. Visibility-only facet fallback retains `idx_audio_search_facets`; mixed predicates retain their original parameterized filters. This prevents a filter-index outer loop from reopening a positional MATCH once per eligible file, including when ANALYZE statistics are absent or stale. A very broad MATCH with a highly selective filter and no retained ranking can instead incur a linear pass over matches; latency still needs measurement for the actual data and filter selectivity. The eligibility probe, filter projection/intersection, membership scan or chunked join, closure rollup and current folder hydration all use the same pinned transaction. Facets continue to ignore result pagination, sorting and selected-folder scope.

The design follows SQLite's [covering-index guidance](https://www.sqlite.org/queryplanner.html#covidx) for avoiding table fetches when the index contains every needed predicate/output, and its [CROSS JOIN loop-order contract](https://www.sqlite.org/optoverview.html#manual_control_of_query_plans_using_cross_join) for keeping ID chunks outside covering lookups and a single MATCH traversal outside fallback file lookups. PostgreSQL's [bitmap index combination](https://www.postgresql.org/docs/current/indexes-bitmap-scans.html) provides the research basis for intersecting ID sets before fetching rows. Here that intersection is explicit bounded Rust work, with BM25 order retained separately; it is not a claim that SQLite automatically combines every filter index or that every mixed filter is covering.

Cache admission also protects smaller working sets from broad fragment queries: a new ranking larger than 524,288 IDs is not retained if its net unique-payload replacement would exceed the remaining ID budget. Canonical sharing is considered before admission, so an identical ranking can add a query key without duplicating its ID payload. This avoids cyclic LRU misses when several million-match queries exceed the unique 32MiB budget together. The current request still uses its complete computed ranking; counts, BM25 order, cancellation and revision checks are unchanged. Small rankings retain normal LRU replacement.

User annotations and filesystem fingerprints are independent. Rescanning must not overwrite annotations. File discovery and header/chunk Metadata extraction are separated from expensive Waveform/FFT work. Scan queues are bounded, writes use batch transactions, and cancellation stops further production and publication. Missing files can only be reconciled after successful enumeration of their scope; inaccessible or cancelled subtrees cannot be treated as deletions.

Metadata probing uses scoped Rust workers (automatic CPU selection capped at eight; CLI `scan --workers 1..16` overrides). Enumeration and probe-result queues each hold at most twice the worker count. Workers own their read connections and never write the database; one consumer preserves batch commits, ordered progress and annotation merging. Prepared statements, per-batch folder IDs and a consolidated header update reduce writer work. Ordinary ID3 tags seek past binary frames, while complex/malformed layouts retain the bounded compatibility decoder. Search selects sorted IDs before hydrating Metadata, and FTS directory facets stream into per-folder counters before closure rollup in the same read snapshot. Rollup fixes the direct-count outer loop and descendant index lookup, then materializes scalar primary-key folder hydration. Stale tiny ANALYZE statistics cannot reverse this into quadratic closure or folder scans; missing ancestors remain omitted. A required missing descendant index is repaired in same-schema owned upgrades before read-only use. See [scan/search performance](Rust_Scan_Search_Performance.md).

Scanning exposes cooperative pause/resume/cancel in the persistent desktop progress strip, Scan menu and library manager. Pausing retains the bounded queue, partial batch, counters, session and scan lease; producer/consumer workers wait without retaining database writer locks. Cancellation wakes paused workers and discards uncommitted batches. Filesystem calls and active batch transactions drain before acknowledging a pause/cancellation. Final reconciliation is a separately reported atomic phase whose controls are disabled; it aggregates audio once per folder before rolling up ancestor statistics. GUI progress is throttled and coalesced into at most one pending event. Resume continues only the current process's scan, not a scan from a previous application session.

A per-database OS file lock serializes scans across providers and CLI processes. An overlapping scan returns a clear Busy error; process exit releases the lock, and the sidecar file remains to avoid an unlink race. A subsequent lease marks abandoned running sessions failed. Directory registration repairs parent links, descendant depth and closure relations after child-first imports, while rescanning an existing root preserves its known parent. A changed file replaces probe-owned BWF/iXML fields, clearing removed chunks and their FTS5 terms while retaining user annotations and unknown extension fields.

Whole-library maintenance and restore hold a separate exclusive `.admin.lock` lease from validation/backup through installation or rollback. Every ordinary provider writer holds the shared administration lease until its transaction/connection guard ends; scans still allow normal annotations. Current-schema opens share the lease and schema upgrades require exclusive access. The protocol covers current Rust clients; external SQL tools or older clients do not participate. Restore normalizes page size only in the owned staging copy before installing into the existing WAL connection.

Alternative-order page plans keep count, ordering and late Metadata hydration in the caller's pinned transaction. Broad duration sorting may use the existing compatible nonpartial single-column `idx_duration` and one uncorrelated `IN (SELECT rowid ... MATCH ?)` for 32,768–2,097,152 matches, without folder/additional filters. Visibility must be All or Present with a same-snapshot proof that every row is present. Native raw duration/NULL order and ascending ID ties remain unchanged in both directions; only the selected page hydrates wide Metadata. Unsupported requests or optional indexes retain the complete ordinary SQL path; no new schema/index is added.

Filename sorting has a narrow complete-candidate path for nonempty Present queries without selected-folder scope and with no additional filters beyond sample rate/duration. It collects complete bounded unscored MATCH IDs, intersects complete narrow filtered IDs when needed, derives the full filtered count from that set and orders through the verified existing `idx_audio_visible_name(filename COLLATE NOCASE,id) WHERE missing=0`. The optional filter index must also have its exact known definition before being forced. With no extra filters, query IDs alone are used only after an all-present proof in the same pinned snapshot, including exclusion of NULL/nonbinary missing values. Sorting preserves `NOCASE` and explicit ascending ID ties for either direction, and hydrates only the selected page. Query/candidate vectors are each bounded to 2,097,152 IDs; JSON/SQLite membership and in-flight allocations are additional memory, not a total-process cap. Missing/incompatible optional indexes, unsupported shapes or budget overflow select the complete fallback; SQL/data errors and cancellation propagate. These local IDs never become a ranking-cache entry.

## Audio pipeline

Default scanning recognizes WAV, FLAC, Ogg Vorbis and OGA/Ogg FLAC. A bounded parser
extracts repeated and Chinese Vorbis comments into `wav_metadata.vorbis` and canonical
`fields`, retaining unknown textual keys, replacing invalid UTF-8 and excluding picture
payloads from Metadata search. Comments use a 1 MiB extraction budget, at most 4096
entries and 16 KiB per retained value. Fingerprints include the non-WAV extraction
revision (`vorbis_version=1`), so incremental rescans refresh old extraction while
preserving user annotations, unknown extensions and the independent vendor mirror.
The raw source text participates in the existing main FTS projection without new columns.

Symphonia features provide FLAC/Vorbis playback and seeking through the same probe and
registered `ByteSource` interfaces as local files; detected container bytes determine
the codec even for opaque stream identities or a `.wav` cache name. OpusTags can be
probed, but `.opus` is not scanned by default and this build explicitly rejects Opus
playback because no Opus decoder is bundled. Chained Ogg probing uses the first logical
stream. Pictures are not extracted into searchable text. Playback metadata options
request a 1 MiB tag limit and no visuals; the embedded readers also rely on physical
FLAC block/scoped-stream bounds and Ogg's 16 MiB packet bound, rather than a claimed
1 MiB total playback-memory guarantee. New codec and migration acceptance remains
separate from the historical measurements below.

The playback engine has a dedicated control thread. Decoding and Rubato resampling run outside the output callback, which consumes a bounded PCM buffer. Output uses CPAL 0.18.2: Windows offers WASAPI and optional ASIO; macOS exposes CoreAudio. The existing `wasapi` preference spelling remains compatible for the default CPAL host, while the Mac UI labels it CoreAudio. Imported ASIO preferences select the default CoreAudio host and reset the device, buffer and rate policy, retaining audition controls. Symphonia 0.6.1 supplies streaming decoding, with RIFF/RF64 chunk handling for WAV Metadata and large PCM files.

On macOS, CPAL's recoverable `Xrun` notification increments the underrun counter, and `RealtimeDenied` leaves playback active. Neither sets the fatal stream-error flag or clears an earlier fatal error. Device loss, stream invalidation and other error kinds retain sticky failure handling; non-Mac hosts retain their existing classification. This callback path uses only atomics, with no allocation, logging, blocking synchronization or application I/O. Acoustic/device acceptance is recorded separately from these error-classification contracts.

Compressed seeks use the decoder's actual timestamp and discard frames before the requested position. WAV IMA/MS ADPCM uses complete compressed blocks with bounded decoding and trims the fact-declared tail. This preserves segment alignment, Waveform positions and end-of-file duration without loading a full file.

Playback states distinguish empty, loading, ready, playing, paused, stopped, ended and error. GUI controls reflect confirmed engine state. Pause preserves position; seek rebuilds the decode stream; gain changes apply while playing. Position is measured in audio frames/time, not wall-clock assumptions.

WASAPI output is released on the control worker after 500 ms in Ready, Paused, Stopped or Ended. Pausing alone leaves CPAL's Windows audio client connected, which can interfere with an external DAW using the same hardware through ASIO. The short grace period retains rapid audition reuse; an expired idle connection stays closed until an explicit Play. Release preserves the source, cursor, audition settings and playback session, while clearing the actual output-route fields. Playing includes network buffering and never enters this idle policy. ASIO output retains its existing lifecycle. Hardware-specific DAW coexistence requires a separate same-device acceptance check.

Seek, Pause, Stop and Load use an 8 ms raised-cosine envelope per channel, sized from the device sample rate (at least 32 frames); a fixed frame count shrank to 0.33 ms at 96 kHz and its linear corners were audible as clicks. The control worker waits for the callback to fade out and stop consuming old PCM before opening/seeking the replacement decoder; slow file or NAS opens happen while the device emits silence. Publishing fresh PCM arms a zero-origin fade-in. Pause and Load drain queued device audio before pausing, including WASAPI's retained queue and both ASIO buffers. Decoder preparation failures drain the old fade before closing output. These waits and decoder operations run only on the control worker; the callback uses atomics and preallocated storage.

An independent transport revision advances with confirmed clock discontinuities such as Seek, repeat, Stop, Pause/Play and stream rebuilding. Position and revision publish together without changing source generations or play-session identity. The UI passes this clock identity into Slint so deferred/coalesced status updates cannot lose a Seek reset. Frame-clock prediction bridges ordinary snapshots using the confirmed Rate and stops after 100ms without new progress. Wheel zoom resolves its anchor from the displayed range while accumulating the requested zoom, preserving pointer time when asynchronous rendering is pending.

Playback history uses a successful play-session ID in addition to the loaded-source generation. First playback, Stop→Play and Ended→Play start sessions; pause/resume, seek, output/transform changes and automatic repeat retain the session. PlaybackStarted events carry the immutable source path, generation and session ID, so quick source changes cannot retarget history to the currently selected row. Library changes discard pending events from the previous library.

Device-rate playback preserves the selected device clock and resamples files as necessary. Native mode requires a supported source sampling rate and never silently resamples. Native rate alone does not establish bit-perfect output; gain, conversion, output sample type and channel processing also matter.

ASIO driver selection uses x64 registry identities and CLSID deduplication. The user's Zen Go registration has two aliases for the same driver and 16 reported output channels. Listening channels and actual buffer configuration are explicit. Driver reset, disconnection or occupied-device failures must recover outside the realtime callback, falling back to paused WASAPI when recovery fails.

Opening the ASIO panel while a stream is active reuses that driver's existing lease. Playback status publishes actual source/output pairs and rate policy only after the output opens, and clears them when it closes. The UI therefore displays the live route rather than saved preferences. WASAPI fallback selects outputs 1/2 and device-rate resampling, with playback paused.

Waveform analysis streams per-channel min/max summaries and optional Spectral Peaks color information. Cached data has an algorithm version plus source fingerprint and is requested for a viewport/level rather than as full source PCM. Algorithm version 4 invalidates former centroid/gray-noise colors and compressed-seek caches. Centered Hann FFT windows keep approximately 5–10 Hz frequency resolution across typical WAV sample rates. Tonal concentration subtracts a local broadband floor, gates weak evidence and fades to the normal black peak; squared-tonality weighting keeps random noise frequencies from skewing a tonal hue. UI display gain, opacity and saturation controls do not alter PCM. Viewport generations keep image, ruler and seek mapping consistent. In server mode, zoom, pan, style and resize requests retain the selected original library record's ID and Metadata even while the preview is Ready; preview paths are not converted into a new ID-0 library record.

The result table keeps native scrolling and prefetches adjacent results within two screens of a moving viewport. Its resident window grows in 200-row steps up to 600 rows, then slides in either direction. Publication anchors the first visible audio ID and fractional row offset, so growing or trimming the window preserves the visible content. Existing search cancellation and generation checks discard superseded ranges; programmatic viewport restoration does not start prefetch. Search tasks retain the window's starting offset and restore enough rows for the saved viewport. The footer reports the loaded page range; explicit pagination and selection of loaded results remain available.

The result table's Waveform column shows 128-column list thumbnails (int16 min/max; doc/api §9.3). A single background worker (background thread mode) serves the visible rows plus one screen above and below. It first looks up stored rows (`waveform_cache`, version `list128-v4-l1`, keyed by size and modification time; this never decodes). In local mode it then computes missing rows one file at a time. On-demand decoding of a row that scrolled out of the window is cancelled. The worker starts no decode during the first 3 s after an audition Load/Play/Seek, and with "pre-generate list Waveforms" on (default off) it backfills the library at up to 5 files/s. Backfill pauses during auditions and for 5 s after one, as well as during scans. Unlike the server's pre-generation (§9.3), local backfill also starts at startup and when the toggle is switched on, not only after scans. Server mode uses the batch API instead and never decodes or reads the snapshot's rows (see Rust_Remote_Mode.md).

Audition uses bundled SoundTouch 2.3.2 on the audio control worker after device-rate conversion and monitor-pair selection. Pitch (−24..24 semitones) and tempo (0.25..4) are independent; identity settings bypass processing. Output uses bounded stereo blocks and an exact duration budget, while position converts consumed device frames back to source time. Transform changes rebuild the source at the confirmed current position and preserve pause. Whole-file repeat reuses the loaded source without another history generation; it is control-thread repeat, not a promised gapless edit loop. A FIFO Synchronize command confirms pending transforms before exit preferences are saved.

## Runtime state and local control

Each user-data directory has a persistent desktop instance sidecar. An exclusive OS lease is acquired before database initialization or preference writes; another desktop using the same root exits with an explicit error. Process exit releases the lease without deleting its identity file. Ordinary CLI commands validate existing Rust library identity/version and only initialize a missing default library; explicit creation and legacy import remain separate operations.

Windows default state is `%LOCALAPPDATA%/AudioLibExplorer/v1`: `library.db`, `settings.json`, `cache/` and `logs/`. Mac desktop and bundled CLI state defaults to `~/Library/Application Support/AudioLibExplorer/v1`; validated beta/rc bundles use the sibling `beta` directory. An explicit `AUDIOLIB_DATA_DIR` takes precedence before reading package markers. Without it, executables inside `.app/Contents/MacOS` validate paired `update-channel.txt` and `update-version.txt` files in the sibling `Contents/Resources` directory; adjacent stray files are ignored. A matching plain version with `stable` selects `v1`, while a matching `beta.N` or `rc.N` with channel `beta` selects beta state. Only that validated beta case respects `AUDIOLIB_BETA_DATA_DIR`; stable bundles ignore it. Missing, partial, unreadable, malformed or mismatched bundle markers fail before selecting a default root. Unbundled CLI/development executables retain adjacent markers; only those unpackaged runs may use `v1` when both markers are absent. Resolving a default Mac home requires an absolute `HOME` unless an applicable explicit override supplies the root.

These defaults preserve configured library paths and keep state outside program files. Earlier unpublished Mac data under `.audiolib-user` is not automatically moved or removed; an explicit `AUDIOLIB_DATA_DIR` can continue selecting it. Relative legacy database paths resolve against the legacy configuration's project root.

`settings.json.active_database` persists the canonical selected database path; old settings without this field use the default. New/open library operations validate the replacement before saving preferences. CLI `db use` affects the next launch and, like CLI restore, requires no running desktop instance; runtime switching is performed through the desktop manager. Selection never imports or overwrites an existing legacy database in place.

Legacy YAML is read only before Rust settings or a Rust library exist. Initial desktop and default CLI startup persist inherited preferences after successful database initialization, so later launches do not depend on an obsolete YAML file.

Fatal desktop startup failures write a synchronous `logs/AudioLibExplorer-startup-error.log` even when preference parsing fails before tracing initialization, and show a native Windows or Mac error dialog. A Mac root/package-marker failure uses a temporary startup-log directory when the normal root cannot be resolved. Headless/UI smoke modes suppress the modal dialog and return a failure exit code.

Local library initialization runs behind a responsive startup panel with bilingual stage text, elapsed time and an animated progress bar. Server-mode GUI startup uses a small placeholder and delegates cache loading/upgrades/downloads to the library manager's single sync pipeline. It checks the remote revision before preparing an old cache that might be replaced; offline fallback accepts only a matching endpoint. Cache-copy percentages count SQLite pages from the pinned read snapshot and describe the copy stage only; download percentages count received bytes. Integrity checks, index upgrades and other unknown-duration stages show an animated segment without an estimated percentage. Worker statuses return through the Slint event loop; background publication cannot replace an active progress message. Closing drains initialization and cache work before releasing the desktop instance lease.

Playback CLI commands use a per-user Windows named pipe. It rejects remote clients, bounds messages to 64 KiB and times out stalled requests. The control protocol carries JSON commands/status only, never PCM. No HTTP service is created; Mac desktop playback does not expose this Windows pipe.

Desktop close captures all outstanding Metadata drafts, then drains their FIFO before cancelling and draining scanning and remote cache preparation. The worker retains its completion in an owned mailbox. Only while closing, UI-thread single-shot timers consume that result; a failed cross-thread event-loop notification cannot strand the Saving changes window. Remote sync owns its busy guard on the worker and releases it after cache work, independently of UI delivery and cancelled generations. A failed Metadata save also waits for cancelled remote preparation before restoring the window and sync indicators. Success hides the retained window before exiting the loop, while a failed save restores drafts and the usable window for retry. Polling stops after completion, shutdown or window destruction and adds no idle activity. A five-second diagnostic warning does not abandon pending writes.

Mac App-menu Quit, Cmd+Q and Dock Quit are intercepted before the first startup event loop. The main-thread guard preserves the pinned Winit delegate, adds only its missing termination query, cancels immediate AppKit termination and dispatches the existing Slint close request. Startup cancellation and the controller's Metadata/scan/dialog drain therefore share the same path. Unknown delegate implementations fail initialization rather than being replaced. The guard stays alive through shutdown, and callback panics cannot unwind through AppKit. Native package acceptance exercises the application's own termination action with a pending draft in a marker-validated, single-record synthetic library; its CLI persistence check does not substitute for human Cmd+Q or playback acceptance.

The JSON envelope retains success, error, error_code, warnings, metadata, execution_time_ms, timestamp and data. An unavailable desktop or invalid playback operation returns an error instead of a fictitious successful zero-value status.

## Delivery boundaries

The first release provides folder browsing, search/filter/sort, cancellable WAV scanning, Metadata display, database-only annotations, favorites, Waveform and transport. Playlist/project-reference data is retained, while their new UI/parsers, standalone spectrum, external plugins and REST providers remain deferred.

Windows client builds target x64 with Rust 1.97.1 MSVC and a static C runtime. The Slint software renderer avoids dependencies on a developer-specific Skia toolchain. The executable manifest requests asInvoker, PerMonitorV2 and long-path support.

ASIO preparation pins Steinberg SDK 2.3.4 and checks the official archive's SHA-256 before setting CPAL_ASIO_DIR. Cargo also defaults this variable to the fixed workspace SDK directory, so enabling ASIO without preparation fails rather than downloading another SDK during compilation. The portable package includes third-party notices and dependency versions. Routine builds use the fixed `dist/latest` output. Public redistribution is separate from this local-use delivery and must satisfy the selected SDK license.

Mac client packaging uses the pinned native arm64 toolchain without ASIO, declares a macOS 11 minimum and includes the GUI, CLI, icon, public documentation and license notices in one `.app` ZIP. It defaults to ad-hoc signing and is not notarized. Build proofs bind a clean exact commit and unsigned binary hashes; package proofs bind signed files, executable permissions and the archive checksum. Native startup, Quit persistence and package acceptance are separate from building/signing and remain release gates. See the [Mac client guide](https://github.com/Freedragonlancer/AudioLib-Explorer/blob/main/MACOS_README.md), [versioning workflow](Rust_Versioning.md) and [measured validation](Rust_Validation.md).
