## UPGRADE-001：升级恢复已补修，Mac 同机性能复测暂缓

Mac 报告的 909,342 条库首次打开 954 秒（分词 411 秒、FTS5 542 秒）、18.9 GB WAL 和停机快照残留属于发布阻断。`47ddd03` 至 `c0e8af9` 不进入本次 Release，8790 保持现有部署。

后续代码增加可恢复的分批分词/索引、本地进度与取消、检查结果的 WAL 截断，以及服务端停机缓存清理。阶段、回退备份和维护期 503 的边界见 [升级恢复说明](Rust_Upgrade_Recovery.md)。用户明确要求暂缓原 Mac 同机复测，先以代码审查和功能验证验收修复；该项性能复测不再作为本轮继续交付的前置条件。功能测试和 Windows 实测只证明对应环境的结果，没有否定原 Mac 报告，也没有新的 Mac 启动耗时。正常快照缓存与保留的回退备份仍占空间，不能承诺零额外整库副本或固定空闲空间倍数。

下列 SEARCH-001 的搜索性能限制独立保留，升级恢复修复不等于整体性能验收完成。

## SEARCH-001：首次搜索与目录统计的完整 500ms 目标尚未完成

### 当前阶段结论：b49f7d2 的 GUI 测量仍有有效慢样本

本轮按用户要求进行阶段收尾、审查和推送，停止继续扩展优化。主要目标仍是 **P95 latency <500ms for 1M+ records**；当前结果不能宣布完整达标。

- 909,342 条真实音效库的 14 类 synthetic Slint 输入：**14 有效、0 无效、4 个有效样本达到或超过 500ms，P95/最大均为 933.151ms**。该库未满百万条，不能代替百万条验收。
- 1,000,000 条合成库的 14 类 synthetic Slint 输入：**14 有效、0 无效、2 个有效样本达到或超过 500ms，最大 568.9038ms**。这些有效慢样本必须保留，不能当作无效样本或用后续快样本替换。
- 百万库 case 12：`ambient`、48kHz、0–5s、filename 排序，从 `e45dcef` 的有效 GUI 总计 **1,673.8516ms** 降至本阶段 **125.9468ms**；但真实库同类请求本次仍为 **584.7215ms**。局部改善不代表全部请求或总体目标完成。
- 上述计时包含生产输入处理、适用 debounce、页面与完整目录模型发布，终点为合格 WGC compositor frame；synthetic Slint dispatch 不是原生 OS 键盘输入，也不是物理屏幕扫描输出测量。OS 页面缓存未清空。
- 真实库 14 类原生 Sky 输入核对：**14 有效、0 无效、1 个有效慢样本，P95/最大均为 609.3829ms（`metal`）**。结果页及全部目录计数均与 oracle 一致。三组共 42 个有效样本中有 7 个达到或超过 500ms；阶段性能验收未通过。
- **原定 224 样本完整矩阵尚未开始，按本次阶段收尾要求延期。** 这批 42 次阶段测量不能替代该矩阵或跨负载的长期 P95 保证。本轮安装与推送不表示性能目标完成，后续需先定位排名及首次文件读取的慢段，再决定是否扩展已有 worker 的评分范围。
- 已交付契约包括 30ms debounce 与双 worker 取消/代次保护、同快照有界冷 MATCH IDs、非阻塞完整排名 peek、窄覆盖过滤交集、稀疏复杂查询逐命中文档长度、duration/filename 覆盖排序及分页后 Metadata 加载。预算溢出仍完整回退，查询、计数、排序和取消语义不截断。具体边界见 [架构说明](Rust_Architecture.md)。
- 空页菜单动作已改为稳定 enabled 加实时安全 guard，避免仅因空/非空转换触发原生菜单重建。此前零命中无效样本的几何记录与源码高度支持该原因，但原报告只保留综合 visibility 布尔值，未严格定位失败的单项检查；其状态仍是无效。WGC 可见性、前台、覆盖、遮挡及同步几何门禁均未放宽。

### 历史后端测量与前轮缓解（保留原口径）

下列后端实测属于 `tokenization=2` 的前一正式构建。当前 CR 已将派生编码修订为 3，并补修 COUNT/非相关度回退；新修订和 GUI 输入到完整显示需要单独验收，不能将旧后端结果解释为当前 GUI 的端到端保证。

- 登记日期：2026-10-19；0.4.7 本地开发构建。
- 状态：2026-10-20 已增加真实音效库验收：909,342 条、20,248 个目录、约 19.49GB，12 类请求各 30 个独立进程，首次搜索加目录统计总计 **P95 277.78ms、最大 293.20ms、0/360 达到 500ms**，全部有序页面 ID 和精确目录计数与修复前一致。真实库未满百万条；同一正式 release 的原百万条合成基准 21 类首次总计 P95/max 为 **215.23/283.85ms**，100 次共享 provider 总计 P95 为 200.69ms。目标仍为 **P95 latency <500ms for 1M+ records**。
- 已缓解：相同完整排名共享唯一 ID 数组，保留 32MiB ID 缓存预算及大型条目准入保护；同修订文档长度缓存和精确 IDF 早停保持原生 BM25 分数；筛选 ID 先与完整排名交集，宽泛密集集合通过位图和目录覆盖索引顺序计数，稀疏集合保留分块回退。完整结果、排序、计数和取消语义保留。
- 复测：真实库采用 `search-benchmark --existing-db <真实快照> --first-only --request-file <固定请求数组> --case-index <0..11>`，每次新进程仅一条首次请求，所有全库统计放在计时后。原合成协议仍为 `--queries 100 --fragment-cases --folder-facets --first-provider`，保留测前统计，须区分两种口径。硬件、数据规模、缓存条件与结果见 [验证报告](Rust_Validation.md)；目录统计的顺序服务计时不能等同于 GUI 首批文件显示延迟，GUI 两类工作仍并行发布。
- 本轮修复：真实 `ambient` 加 48kHz、0–5s 筛选的旧总计为 **62,484.31ms**；小排名交集准入和 FTS5 外层回退修复后，30 次正式总计 P95/max 为 **185.49/186.14ms**。预算溢出仍完整回退，新增回归覆盖无/旧统计、小排名缓存、候选溢出、NULL 可见性及目录/分页契约。前一轮八段评分、七个辅助 reader 准备及有界通道修复继续保留；每连接 SQLite cache 为 64MiB，mmap 为按需使用的 64GiB 配置上限，资源边界见 [架构说明](Rust_Architecture.md)。
- 剩余范围：OS 页面缓存未清空，最终测量在没有并行构建或应用升级重负载的空闲窗口执行，不保证其他生产资料库、物理冷盘、任意系统负载或完整 GUI 端到端都小于 500ms。无缓存且 MATCH 极宽、筛选极窄时，FTS5 外层仍需遍历匹配集；实际选择率需要继续实测。旧批次复杂总计 601.37ms、失败候选 621.72ms、混合筛选 4514.68ms、中间标签筛选 724.87ms 及本轮真实 62.48 秒记录全部保留，不据重测推断未证实的单一根因。最新完整口径、全部样本和构建身份见 [验证报告](Rust_Validation.md)。

## UI-001：失焦后重新聚焦，界面内容丢失

- 登记日期：2026-10-12。
- 状态：0.4.4 已修复重绘逻辑，复用 buffer 回归通过；2026-11-02 已在 0.8.7 Windows ASIO 候选及最终 main `b5a98ff98fed` 实际 payload 上分别完成 Default / Studio 的前台、遮挡及最小化恢复验收，保留各自工具和二进制身份。
- 用户报告：软件失去焦点后，再次聚焦时 UI 大面积消失或变黑，仅部分按钮和局部控件仍然可见。报告截图处于音效库管理的服务器设置界面，原因为待查，尚不能认定数据或窗口状态丢失。
- 复现线索：打开音效库管理 → 切到其他窗口 → 返回 AudioLib Explorer。出现频率、最小化/遮挡是否必要、缩放与显示器组合尚待确认。
- 修复：Slint 1.17.1 软件 renderer 可能按 buffer age 复用已被 Windows 清空的表面，而 Windows 不保证发送 Occluded 通知。Windows 原生 RedrawRequested 标记完整逻辑窗口，恢复事件请求重绘；保留原组件、草稿与选择，无定时重绘。2026-11-01 收窄：窗口子类在 `WM_PAINT` 时检查更新区域，只有 Windows 真正失效像素（更新区域非空）或聚焦、遮挡恢复、尺寸变化之后的那一帧才标记完整窗口；Slint 自己请求的动画帧（`RDW_INTERNALPAINT`，更新区域为空）保持局部重绘，播放时不再每帧整窗重绘。无 HWND 或无法挂接的窗口仍按完整窗口处理。后续两主题原生复验见下文。
- 历史验证：确定性回归先验证 request_redraw 单独使用不能恢复清空的复用 buffer，再验证完整损伤恢复整帧、表单和选择保持、空闲不重绘。当时 ASIO release 的自有窗口 DC 抓帧在 192 DPI、1094×630 client 下完成失焦/遮挡/最小化各三次操作，像素保持。
- 历史实机限制：当次 Windows 会话锁定，input desktop 不可访问；自有窗口表面检查不代表前台焦点和真实暴露转换已验收。工具明确记录 `foreground_exposure_verified=false`，未使用会触发重绘的 PrintWindow 来替代验收；这些旧结果不改记为通过。
- 2026-11-02 工具修正与复核：早期工具误用 `MainWindowHandle` 可能选中同 PID 的 winit utility 窗口，导致空白基线；失败清理误关该窗口还会破坏事件循环唤醒投递。改为唯一可见应用窗口的 PID、标题及类名复核。另在 HWND 创建时固定遮挡窗的原生 topmost/toolwindow 样式，避免托管 `TopMost` 状态与实际遮挡不一致；最小化使用自有备用焦点窗口及短暂自有队列绑定，并在 finally 解绑定。通过物理覆盖范围、四角/中心命中、真实前台/最小化状态确认操作发生，原内容与像素差异阈值未放宽，无应用 Rust 改动或重建。
- 候选实测：同一 beta 应用提交 `86acdac21468` 的 EXE SHA256 `4bd1265d2c31c5e6856c60732e495ca74ffa3b25f33f05a10f49d7508fec3061`；192 DPI（200%），Default client 2214×1370、Studio 2214×1409。各自失焦/聚焦、保持前台的遮挡恢复、最小化/还原各三轮，共十八轮均通过，逐轮采样 `changed_fraction=0`，`foreground_exposure_verified=true`、`normal_shutdown=true`。原报告为 `.rust-validation/window-repaint/default-8ab756a0305f4807afedce875d918e33/report.json` 与 `.rust-validation/window-repaint/studio-ad83e26572f74a069fb6c0eef99b9e08/report.json`，保留候选身份，不用它代替最终 payload。
- 最终 main 复验：`b5a98ff98fed501aafff0f6a4ef5015c8b4d435d` 实际 EXE SHA256 `859541a34d4eb05a04ddcda4f92d88596253235bc8ad1ed66a723999489faf81`；首次 Default refocus 未使遮挡窗取得前台，失败与 facts 保留，不能将具体 Windows 策略或超时原因写为已证实结论。随后仅在工具中复核当前应用窗口并通过两个自有队列短暂绑定进行焦点交接、finally 解绑定；独立工具提交 `2d25272cf0a37678e5b2a178c1079e8ca859e1c1`、SHA256 `d0344e7a28f91d6b0044d3dac0e5e2043ff6a7eecb2bbe07e39cc933751cbc79`。原层级、前台、遮挡与像素门禁未降低，应用 Rust 未改、payload 未重建。
