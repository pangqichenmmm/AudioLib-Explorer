# Rust 音效库管理

桌面以音效文件夹的添加、扫描更新、缺失引用修复、标注和历史为日常入口，数据库专业工具收在默认折叠的“高级维护”中。桌面与 CLI 均通过 `DataProvider` 调用同一服务；不会修改或删除源 WAV。当前可写 schema 为 v8，使用共享专辑实体，Metadata 保持原始 JSON TEXT；Metadata 压缩暂缓，详见[共享专辑与存储](https://github.com/Freedragonlancer/AudioLib-Explorer/blob/main/doc/Rust_Shared_Albums.md)。已有 Rust 库通过共享迁移器完成备份、断点恢复、校验及发布；远程快照按完整格式目录支持 v3 至 v8，原快照保持只读，旧来源在 owned 副本中投影为 v8，并单独保留源格式供同步判定。详见[迁移契约](api/Library_Migration_Compatibility.md)。既有评分列及数据保留，产品接口不再提供评分编辑。旧 Python 库应导入副本，保留原库供回退。

普通本地库切换（包括从服务器模式返回）只执行既有库身份、schema/feature 版本、必要结构和迁移状态检查，并保留跨实例锁、Metadata 写入和扫描排空保护；不再为每次切换复制全库并执行完整一致性校验。首次添加已有数据库及显式完整性检查仍执行 owned 副本校验；确需格式升级时，迁移器仍创建回退备份并校验候选库。切换等待界面显示保存待处理写入、等待扫描、打开数据库、迁移进度、准备搜索和应用设置等阶段；日志通过 `stage`、`elapsed_ms`、`success` 记录阶段与总耗时，不记录连接凭据。当前格式库的普通切换不会主动发现所有潜在数据损坏，需要时使用高级维护中的完整校验。

## 桌面操作

封面管理支持本地和服务器模式的显示开关、手动指定/替换、移除、恢复内嵌封面、重新加载及清理本机缩略图缓存。共享专辑内的自动封面和手动选择均按 WAV 的直接父目录区分：同一目录的无图成员可复用该目录的内嵌图片，其他子目录独立取图，不从全专辑前若干条记录借用封面。手动封面保存在本机用户数据目录，绑定当前素材库、共享专辑和直接父目录；不写入 SQLite，不修改 WAV，不与其他客户端同步。清理缓存保留手动图片及隐藏选择。服务器模式入口在活动数据源的“缓存与导出”页，旧服务器也可使用手动封面。详见[封面说明](https://github.com/Freedragonlancer/AudioLib-Explorer/blob/main/doc/Rust_Artwork.md)。

旧全专辑手动图片或隐藏选择保持只读继承；当前目录的显式指定、隐藏及恢复内嵌封面优先。恢复内嵌封面会为当前目录保留“忽略继承选择”标记，以便显示该目录的真实 WAV 图片，不删除其他目录仍可继承的旧偏好。目录封面规则不拆分共享 Album 实体，也不改变 schema v8 或原始 Metadata TEXT；Metadata 压缩仍暂缓。

“音效库管理 → 本地设置”的数据源列表支持多个独立本地音效库。首次使用将原有工作数据库登记为 `default`，保持数据库路径和所有标注；`default` 无法移除。“＋ 添加源”可选择本地音效库路径或服务器音效库，后者进入服务器连接设置。本地表单提供名称、简介和默认勾选的“预生成列表波形”：选择 WAV 文件夹时，在用户数据根的 `local-libraries/` 下新建独立数据库，切换后后台扫描；勾选“添加已有本地音效数据库”则校验并登记已有 `.db`，保留其 Metadata、标注及扫描历史。

各本地库独立保存波形预生成设置。扫描结束后，后台用与服务器相同的简化 Waveform 算法补齐列表缩略波形，并显示本轮已处理、已生成和失败数量；扫描或试听期间显示等待状态并让出资源。计数是本轮工作量，不虚构未知总量或完成百分比。切换库先排空 Metadata 写入并取消、等待扫描，旧库的行、搜索和波形结果不能回填新库。移除只取消数据源登记，保留数据库及其标注、SQLite sidecar 和源 WAV；当前本地库需先切换到其他数据源后再移除，已有数据库可重新添加。

本地列表 Waveform 预生成取消了每个文件 200 ms 的固定等待，沿用单个最低 CPU／I/O 优先级工作线程，每完成一个文件重新检查可见行、试听和扫描状态。解码复用服务器的摘要路径，省去完整 Metadata 预读，使用固定 2 MiB 顺序读取缓冲；128 列峰值和已有缓存键保持一致。屏外后台结果只更新持久缓存和文字进度，不向界面逐文件发送无效刷新。

可复现性能验收入口为 `tools/benchmark-local-waveforms.ps1`：在隔离目录生成 120 个 16／24 bit、1／2／4 声道、0.25～16 秒的 WAV，运行真实后台工作线程和 SQLite 缓存写入，逐项验证所有峰值，并确认已有缓存的一轮不再解码。先对旧版本运行 `-Label before`，优化后用 `-Label after -BaselinePath .rust-validation/local-waveforms/before.json` 检查相同工作量并要求至少 10 倍提速。可用 `-FixtureParent <已存在目录>` 把音频放到 NAS，数据库仍在系统临时目录；前后须使用同一位置和机器。这里的冷缓存仅指列表 Waveform 缓存为空，不清空操作系统文件缓存；基准不包含 GUI 绘制耗时。

2026-10-27 的 release 实测：Windows 11、Ryzen 7 9800X3D（8 核／16 线程）、约 96 GiB 内存；上述同一组 120 个 WAV 共 199,925,280 字节。旧基线 `d7d0f2f` 的调度、摘要解码和缓存实现与 beta `5256fa4` 相同。两轮均生成 120 个结果，逐项匹配独立峰值计算，失败为 0，热缓存一轮解码为 0；测试只使用隔离合成文件。

| 音频与临时数据库位置 | 优化前 | 优化后 | 吞吐变化 | 提速 |
| --- | --- | --- | --- | --- |
| 本机 SSD | 24.757 s | 0.428 s | 4.85 → 280.35 文件／秒 | 57.84 倍 |
| SMB NAS（音频及临时数据库均在 NAS） | 24.981 s | 1.814 s | 4.80 → 66.16 文件／秒 | 13.77 倍 |

这些数字适用于上述混合文件和缓存条件；超长文件、繁忙或离线存储的实际吞吐取决于解码与 I/O。基线与优化后的原始报告保留在忽略的 `.rust-validation/local-waveforms/` 中；旧版本测量需先临时接入同一基准模块，保持生产实现不变。

基准脚本只接受本次运行新产生且完整成功的报告；未执行到测试、结果不完整、计时无效或未达到提速门槛时不会覆盖已有报告，基线文件也不能同时作为输出。脚本自身的隔离回归入口为 `tools/test-local-waveform-benchmark.ps1`，使用模拟 Cargo 检查这些失败路径和环境恢复，不调用音频设备或工作库。

Windows 普通路径与标准扩展路径（含 UNC）按相同登记身份处理，临时离线不会新增重复库。数据源表单验证不访问已登记数据库的文件系统，服务器设置仍可编辑；实际本地库在登记和打开时校验。快速修改波形开关后切库会先保留原库设置。保存名称、简介或移除登记期间请求退出，窗口会等待配置写入；保存失败时保留窗口和错误信息。切回本地会立即取消旧服务器同步；若目标本地库已经打开，则保留当前连接和搜索上下文。已转存到恢复文件的 Metadata 草稿仍显示恢复文件位置。

声音列表不再显示行首批量选择方框和收藏星形。单击选择一条记录，`Ctrl` 单击切换单条选择，`Shift` 单击或 `Shift+↑/↓` 连续选择，`Ctrl+Shift` 可追加区间；多选项以行背景区分。区间锚点绑定文件 ID，筛选或翻页后不会沿用失效的行号。右键声音使用“添加到收藏 / 取消收藏”，收藏筛选及既有收藏数据保留。

同一用户数据目录只允许一个桌面实例；第二个窗口在初始化数据库或保存设置之前被拒绝，避免旧配置覆盖新的库选择。实例锁由操作系统在进程退出后释放。

窗口顶部提供常驻菜单栏，支持中文和英文切换；“音效库 / Library”提供音效库管理、缺失文件、扫描历史和最近播放。主工具栏及顶层菜单不展示数据库新建、打开、备份、恢复、FTS5 或数据交换工具。

| 菜单 | 基本操作 |
|------|----------|
| 文件 / File | 添加声音文件夹；退出 |
| 编辑 / Edit | 查看和保存 Metadata；批量标注选择记录；选择当前页或清除全部选择；收藏、复制路径、资源管理器定位、修复所选文件引用；移除所选记录、选择记录或当前目录 |
| 音效库 / Library | 音效库管理；查看缺失文件并修复引用；扫描历史与最近播放 |
| 扫描 / Scan | 增量扫描或全量扫描文件夹/当前目录；暂停、继续、取消当前扫描；刷新素材库 |
| 视图 / View | 聚焦搜索；显示/隐藏详情与筛选；重置筛选；全部声音、收藏及现存/缺失/全部状态；切换语言 |
| 播放 / Playback | 试听所选文件；播放、暂停、停止；音频输出与 Spectral Peaks 设置 |

快捷键：`Ctrl+Shift+I` 添加声音文件夹、`Ctrl+D` 音效库管理、`Ctrl+F` 搜索、`Ctrl+S` 保存 Metadata、`Ctrl+I` 显示/隐藏右侧栏（筛选 / 详情页签）、`F5` 刷新素材库、`Ctrl+Q` 退出。菜单和快捷键在弹窗打开、管理操作执行或退出期间禁用，避免重叠操作；`Esc` 可关闭当前可关闭的弹层。需要选中声音、选择记录或选中目录的选项按当前状态启用，扫描运行时不再启动第二轮扫描。

“文件 → 退出”和窗口关闭共用保存流程：等待已请求的 Metadata 写入，保存失败则保留窗口和草稿供重试；保存成功后取消当前扫描，并在后台等待扫描结束和数据库锁释放后退出。升级或通过菜单打开库不迁移用户数据目录，继续使用 `%LOCALAPPDATA%/AudioLibExplorer/v1`，或已有的显式 `AUDIOLIB_DATA_DIR`；所选库路径按设置保留。

文件菜单仅保留“退出”。添加声音文件夹整合在“音效库管理 → 本地设置”；Ctrl+Shift+I 仍打开文件夹扫描对话框。服务器连接参数在“服务器设置”中编辑；WebDAV 设置显示灰色空白占位“功能未开发”，保存连接时保留原有 WebDAV 配置与凭据。切换设置页仅选择配置，启用仍需“切换到此数据源”。

服务器模式下，在“服务器设置 → 服务器音效库”管理远程资源根目录。服务器返回 `root_management` 能力且允许当前连接管理时，当前数据源可添加音效库、修改资源路径和删除音效库。目录选择器浏览服务器的磁盘位置与子目录，提供面包屑、上级目录和绝对路径输入；客户端不会访问这些路径对应的本地磁盘。添加后由用户开始扫描。修改资源路径要求目标已有相同相对路径的有效 WAV，先验证全部目标并备份，再原子更新数据库引用，保留文件 ID、Metadata、标注及关联。删除需要确认，移除根配置、记录及标注，保留服务器上的目录与 WAV 文件。操作先排空已请求的 Metadata 写入，扫描运行或暂停时不可执行；完成后刷新快照和根映射。旧服务器需要升级后才提供根管理。接口、权限与中断恢复见 [服务器 API §6.10](api/README.md)。

“音效库 → 音效库管理”打开「音效库管理」窗口（左栏为本地素材库和各服务器配置；本地模式下选中本地素材库时右栏即原管理内容），展示声音数量、缺失数量，以及“添加文件夹”“增量扫描”“全量扫描”“修复文件引用”和历史。底部“高级维护”每次打开默认折叠，展开后才显示库路径、版本、新建、打开、备份、恢复、检查、优化、重建 FTS5、全库 JSONL/CSV 导出与标注导入。新建/打开后保存所选路径，下次启动继续使用该库。恢复和移除记录需要在界面确认。管理操作先保存 Metadata 草稿、停止扫描，并在后台执行；切库清除旧选择和后台请求，失败时保留当前库和草稿。

扫描对话框支持浏览选择文件夹，也可直接输入本地或网络共享路径。添加文件夹默认使用增量扫描；管理窗口的扫描按钮在已选目录时预填该目录，没有已选目录时由用户选择。扫描菜单的“当前目录”和文件夹右键菜单均先打开对话框，显示目标路径、所选模式及其作用范围，确认后才开始。通过菜单打开扫描窗口后，输入焦点进入路径框；音效库管理与扫描窗口的键盘操作保持在弹窗内，背景 Metadata 编辑器和试听列表不接收按键。

提交扫描后立即显示文件夹校验状态，路径和模式暂时锁定。校验期间可用“取消”或 `Esc` 取消这次请求；后台文件系统检查返回后解除忙碌状态，取消的请求不会开始扫描或写入扫描历史。路径检查失败时保留窗口和输入，显示原因供修改后重试。

扫描开始后，主界面持续显示扫描阶段、已检查/新增/更新/未变化/问题计数和当前文件路径，并提供“暂停扫描 / 继续扫描”和“取消扫描”。扫描菜单和音效库管理窗口提供同样的控制。暂停请求等待当前文件系统调用或批次事务结束，确认后停止处理；继续沿用本次队列、计数和扫描历史会话。暂停期间可浏览、试听和编辑 Metadata，也可直接取消；取消会保留已提交的结果并丢弃未提交批次，不检测缺失。关闭窗口会唤醒并取消暂停中的扫描后再退出。当前功能不提供退出程序后的断点续扫。

最后的缺失协调与目录统计在同一事务中完成，显示“正在整理扫描结果…”，此阶段暂停/取消按钮禁用，等待事务完成；慢盘或网络文件系统正在执行的调用也需要返回后才能确认控制请求。枚举过程中不预先知道总文件数，因此显示已检查数量，不显示虚构的完成百分比。

增量扫描适合添加新音效和日常更新，按文件大小和修改时间跳过无变化文件，不检测缺失。全量扫描适合文件整理后重新检查，重新读取所选文件夹及其子目录的全部 WAV / BWF Metadata，并协调该范围内的缺失记录。两种模式都包含子目录，均以用户确认的单个文件夹为范围。全量扫描必须完整完成且没有扫描错误，才会把未读到的文件标记为缺失；扫描有错误、取消或无法完整枚举时不作缺失标记。标记缺失保留已有标注，不删除源 WAV。

扫描历史默认展示易读的时间、路径、模式、完成状态和新增、更新、新发现缺失、未变化、错误数量。点击记录可查看结果、错误路径和原因；每轮保留最多 100 条错误明细，超出数量单独显示。最近播放读本机独立历史，默认每库 5000 条，可清空当前库并须确认；提示“仅本机记录，不上传服务器”。客户端两个模式均不调用服务端播放接口。日常历史不默认展示原始 JSON。

结果可切换“现存”“缺失”“全部”。从“音效库 → 查看缺失文件 / 修复引用”或管理窗口的“修复文件引用”进入缺失列表，选中声音后，详情面板会说明原路径缺失，并引导选择移动或改名后的 WAV。修复逐条进行；成功后刷新源 Metadata，保留主键、标签、评分、颜色、备注、收藏及关联关系。目标路径已被另一个记录占用时明确拒绝。文件改名后若已扫描出新记录，先确认新记录不含需要保留的数据，再移除新记录并把原缺失记录关联到新路径；系统不自动合并两个记录。

结果支持多选和批量标注。标签可替换、追加或移除，追加/移除按 Unicode 大小写折叠比较。评分、颜色、备注和收藏只修改选择的字段。整个批次在一个事务中完成；无效字段或不存在的 ID 会回滚整个批次。

“移除记录”和“移除目录”仅移除库内数据及对应关联。移除目录包括其子目录。源文件仍在磁盘，再次扫描可能重新建档，因此在执行前确认选择正确。本次 schema 6 / p1 升级显式退役 `play_history`、`audio_files.play_count` 和 `audio_files.last_played_at`；原始旧值保留在升级前备份，回滚可恢复。本地旧历史先从验证后的备份幂等导入本机 history.db，导入失败不清理主库；服务端和快照不导入。尚未升级的当前工作库不做此清理。

## 备份、恢复和维护

恢复时只在自有临时副本中统一 SQLite 页大小，使有效备份可以安装到页大小不同的当前 WAL 库；原备份保持不变。

备份通过 SQLite backup API 获取包含已提交 WAL 的一致快照，输出为独立 `.db` 文件；已有输出文件不会被覆盖。完整性检查在临时磁盘副本上运行 SQLite quick_check 和外键检查，并按受支持格式检查 FTS5：旧 external-content 格式核对外部内容与索引一致性及同步触发器；v6 contentless-delete 格式核对 FTS5 内部完整性、表与触发器结构，以及业务 ID 与 FTS docsize 成员关系。不修改源库。

恢复先验证并升级待恢复库的临时副本，再为当前库创建自动回退备份。验证成功后使用 backup API 写回当前连接，清空空闲读取连接；失败则恢复自动备份。恢复报告给出 `rollback_backup` 路径。优化和重建 FTS5 也会先创建回退备份。旧 external-content 格式的搜索重建曾更新持久分词列；当前 v6 不再创建这些列，而是从业务 Metadata 投影完整逻辑字段，重建 contentless-delete FTS5 及同步触发器，按需补齐源标签派生状态。维护需要额外磁盘空间，执行结果应保存以便找到回退文件。

扫描、恢复、维护、重新关联、批量操作和移除操作共用每库 `.scan.lock` 排他锁。另由 `.admin.lock` 隔离维护和恢复：普通库写入持共享锁，维护或恢复在备份、执行、安装和回退期间持排他锁，避免另一连接已保存的标注等库数据被旧快照覆盖。独立本机播放历史不属于库快照，不随主库恢复而回退。扫描期间仍可编辑 Metadata。冲突返回 Busy；进程退出后锁自动释放，sidecar 文件保留。备份及导出可读取一致快照。CLI 恢复或改变下次启动的库路径要求先退出桌面程序；运行中的桌面请使用“音效库管理 → 高级维护”，以便保存草稿并更新界面。

## 数据交换

播放行为不写主库，不增加计数、不更新最后播放时间，也不推进素材库业务 revision 或 `data_version`。仅客户端历史库追加每次成功播放会话，写失败报告 diagnostics，不阻塞音频；暂停/恢复、seek、试听变换与 repeat 不重复记录。服务端兼容入口保留 ID 校验和无写入语义；客户端不再发送 plays/history 请求。

导出为全库 JSONL 或 CSV，包括缺失记录，采用流式写出，不受当前搜索页面限制。JSONL 每行一条完整 `AudioFile` DTO；CSV 含基础 Metadata 和用户标注，复杂源字段在 `attributes` 列中以 JSON 保存。导出不是包含播放列表及引用的数据库备份。

标注导入接受上述 JSONL/CSV，按规范化文件路径匹配当前库，只更新标签、评分、颜色、备注和收藏；不创建新音频记录，也不改源 Metadata。未知路径计入 skipped。整个导入为一个事务，格式错误或无效标注会回滚已处理的行。需要整体保留目录、扫描历史、播放列表和项目引用时使用 `.db` 备份恢复。本机播放历史单独保存在用户数据根的 play-history/，不属于素材库快照、导出或远程缓存。

## CLI 示例

普通命令只打开经过身份和版本验证的既有 Rust 库。显式 `--database` 路径或已选择的非默认库不存在时会报错；先用 `db create` 创建新库，或用 `db import` 导入旧库副本。首次默认库仍可自动初始化。CLI 与 GUI 的重新关联都校验解析后的真实 WAV 路径，不能通过文件符号链接绕过 `allowed_scan_roots`。

所有示例在便携版目录运行，默认输出 JSON。对另一资料库操作时在命令前添加 `--database "D:\Audio\library.db"`。

读库子命令（`search`、`stats`）未指定 `--database` 时，会向 stderr 输出一行 `正在使用默认库：<路径>`；`search` 结果为 0 条且当前库文件数为 0 时，stderr 还会提示 `当前库为空，可用 --database 指定库路径`，避免把空库误认为“搜不到”。只写 stderr，stdout 与 JSON 输出不变，`tools/validate-*.ps1` 按 stdout 解析 JSON，不受影响。

## 回归入口

`crates/audiolib-db/tests/library_management.rs` 覆盖事务、WAL 快照、恢复回退、FTS5 修复、只读检查、重新关联冲突、删除关联、全库交换及并发锁。`scan_management.rs` 覆盖 Unicode 缺失协调、完整错误明细、明细上限和 WAV valid bits 清除。`tools/validate-library-management.ps1` 使用 release CLI 和隔离合成文件，输出 `doc/Rust_Library_Management.json`。实际执行结果、性能和桌面检查见 [Rust 验证报告](Rust_Validation.md)。


本地导入以只读来源创建自有副本，最终路径受持久导入锁保护。本地旧格式副本发布后复用内置迁移 job；失败可能保留可恢复的旧格式目标和备份，须 resume/rollback，不能换另一来源覆盖该目标。详见 [v6 升级契约](api/Schema_V6_Iteration.md)。
